# ChemicalOps：化工采购运营平台与场景化 Agent

> 项目周期：2026.09—至今｜整理日期：2026-10-08
> 定位：全栈业务平台 + 大模型应用。以下描述以当前实现和有日期的验证记录为依据，适用于项目展示与面试；个人职责按实际参与范围表述。

## 项目简介

面向化工采购、供应商协同、质量、仓储和财务，构建从采购申请、询价报价、订单审批，到到货验收、库存与结算的业务平台。在业务系统中接入场景化 Agent 和化学品 RAG，支持权限范围内的库存/报价查询、技术资料检索、采购草稿预览及报告核对，让 AI 输出能够关联原始资料和业务记录，并由服务端规则与人工确认约束后续操作。

## 核心贡献

- **全栈架构与业务闭环：** 使用 FastAPI / SQLAlchemy、MySQL 与 Vue 3 构建采购至结算的流程，通过状态机、RBAC 和资源归属校验解决多岗位协作与越权访问问题；实现供应商报价、订单确认、交期、发货、质量资料及对账协同，形成可追溯的本地演示链路，既有供应商/角色及财务定向回归共 37 项通过。
- **Agent 编排与确认交互：** 使用 LangGraph、Pydantic 和四工具白名单解决模型选工具、对象歧义与结果依据不明的问题；以任务快照、revision 和会话引用支持候选追问、人工续跑、取消及历史鉴权，服务端从成功工具结果生成证据摘要。2026-10-03 来源/数值隔离矩阵 30/30 通过；专用采购草稿支持预览确认，通用 Agent 确认写入尚未实现。
- **化学品 RAG 与检索优化：** 使用 Qdrant、MySQL 章节桥接和 CAS / 别名规范化解决名称定位与资料证据检索问题；200 条合成混合题中，149 道可回答题的 Recall@6 为 86.24%、MRR@6 为 0.6842、nDCG@6 为 0.7290，无证据拒答 39/39。后续名称专项回归修复 17 道定位失败题，目标识别 149/149；稳定章节 ID 与条件向量更新另经隔离环境验证，防止重跑重复及旧内容覆盖。
- **财务一致性与审计追溯：** 使用 Decimal、来源 SHA-256、MySQL 行锁和追加式版本解决税额舍入、重复占用与历史依据变化问题；实现发票行匹配、当前额度复核、驳回释放及独立双人核验，以 6 组场景、8 张模拟发票验证流程，支持 0～6 位金额精度并保留历史匹配依据。
- **评估体系与工程验证：** 使用 pytest、固定题集与来源清单验证业务状态、权限、Agent 证据和检索效果；使用 RabbitMQ/aio-pika 与 MySQL outbox 解决 API 进程内任务缺少持久投递与恢复机制的问题。2026-10-08 相关回归 222 项通过，真实 Broker / MySQL CLI 演练验证停机补发、队列隔离和消费者崩溃恢复，Windows/Linux 进程监督与临时 Qdrant 集合验证旧执行隔离；默认仍为进程内执行，队列能力可选启用。

## 项目整体 STAR

### S — Situation：业务背景与问题

化工采购同时涉及规格、供应商、质量资料、到货、库存和财务依据。不同岗位需要共享流程状态，但只能操作职责范围内的数据；对账与开票又需要保留计算口径和历史来源。引入大模型后，还需解决同名化学品识别、查询对象歧义、证据缺失、权限越界和长任务中断等工程问题。

### T — Task：项目目标

建立覆盖采购到结算的全栈平台，明确岗位与供应商的数据边界；将场景化 Agent 和技术资料检索融入现有业务界面，让查询与建议具备可核查的来源，并保留人工确认。对关键金额和状态变更建立事务与审计约束，对资料处理及 Agent 异步执行提供可选持久队列与故障恢复能力。

### A — Action：技术方案与实施

1. **构建业务与权限基础。** 使用 FastAPI / SQLAlchemy 实现业务服务和状态流转，MySQL 保存单据、关联明细与事件；服务端按角色、所有权和供应商绑定校验访问。Vue 3 复用现有列表、表单、弹窗和抽屉组件，将权限控制、来源详情与业务操作放在统一界面中。
2. **将模型行为收敛为可验证流程。** 使用 LangGraph 组织模型决策与工具反馈，Pydantic 约束动作结构，仅开放授权的只读工具。遇到多个候选时等待用户选择，续跑重新核验对象；通过 MySQL 快照和 revision 防止迟到响应覆盖取消或新状态，服务端核对来源和数值。采购草稿通过专用预览接口校验后，由用户确认正式创建。
3. **建立资料检索与可恢复入库链路。** 将原件存入 MinIO，解析为 MySQL 章节并写入 Qdrant；通过名称、别名和 CAS 定位目标，用章节内容及来源支撑回答。重复解析保留章节标识，源 hash 校验决定是否复用 checkpoint；Qdrant 1.16 及以上的条件更新与文档代次阻止迟到写入覆盖新正文，并清理失效章节对应的旧点。
4. **保证财务依据与执行一致性。** 使用 Decimal 处理金额与税额，事务行锁保护当前占用额度，来源 hash 检测依据变化；匹配与核验按版本追加，事件记录保留修改与复核轨迹。异步执行则将业务记录、执行记录、outbox 和资源锁同事务提交，由独立投递器确认发布；两类 Worker 使用租约、token、有限重试与子进程监督，无法证明旧进程停止时隔离并保留资源锁。
5. **用分层验证支撑结果。** 对业务和权限使用隔离事务回归，对 RAG 使用固定合成题集、随机种子和 SHA-256 清单，对 Agent 分开检验工具编排、来源/数值与真实模型样本。使用真实 RabbitMQ、隔离 MySQL、临时 Qdrant 集合及故障注入验证恢复流程，明确替身与真实服务各自覆盖的范围。
