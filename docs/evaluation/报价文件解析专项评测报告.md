# 报价文件解析专项评测

## 结论

本轮已完成文件解析、字段候选契约、真实模型正常样本抽查、扫描件真实 OCR，以及人工修订后录入和成本计算的隔离验证。**尚不满足专项验收放行条件**：四个对抗契约探针发现候选字段与来源的一致性缺口；另有重复导入时表单来源混用风险。

本轮只新增评测、测试和证据，不修改生产 Prompt、Schema 或报价业务行为。后续应先修复这些通用边界，再复跑本套评测；不直接跳到采购全链路验收。

## 验证范围与证据

| 验证 | 结果 | 证据与边界 |
| --- | --- | --- |

| 扫描件真实 OCR 与抽取 | 1 次 MinerU 成功、1 次模型响应，字段符合预期 | [OCR 原始结果](quote-extraction-live-ocr.json)、[对应扫描输入](quote-extraction-live-inputs/scan_without_ocr.pdf)；原始文件 SHA256 可与报告核对 |
| 本地解析定位 | 文本 PDF 第 2 页、Excel Quote 工作表第 6 行均可定位；扫描 PDF 本地无可选文字 | [测试代码](../../tests/test_quote_extraction_evaluation.py) |
| 人工修订后录入与成本 | 修订后的单价 14.25、税率 9%、报价量 20、账期 net 45 days 被报价服务保留；询价量 10、MOQ 20、明确无运费时总成本为 310.65 | 同一测试调用真实报价服务与成本计算器；Session、供应商/单位查询和审计为替身，不代表真实数据库或浏览器链路验收 |

所有文件均为合成数据。真实模型与 OCR 抽查使用同一份英文单行报价内容的不同文件表现，不是四个独立业务场景，不能外推为生产准确率。未覆盖真实供应商文件、中文扫描件、多物料复杂表格、公式缓存、合并单元格和批量长文件。

相关回归共 34 项通过。独立代码复核发现评分答案曾复用模拟响应工厂，已改为按输入文本单独标注，并观察“修改模拟价格/币种不能改变预期值”的回归先失败后通过；最终探针结论不变。该修正针对评测器，不是修复报价候选服务。

反病毒扫描、文件上传、询价权限读取均以替身隔离；仅真实模式调用模型和指定 OCR 服务。不连接业务库，不保存正式报价，不触发中选或订单。已有文件/权限护栏回归单独运行，不把这些替身当成真实上传或权限验收。

## 待修复项

| 编号 | 级别 | 复现与实际行为 | 需要的通用边界 |
| --- | --- | --- | --- |
| QE-01 | P1 | `unsupported_fields`：原文仅有产品、数量和单价，模拟输出补上型号、税率、含税口径、MOQ、交期和账期；合法整行引句存在，七个无依据字段仍被保留 | 明细提供逐字段来源，字段值必须由相应证据支持；不能把“整行引句存在”视为全部字段真实 |
| QE-02 | P1 | `header_mismatch`：供应商原文为 Demo A、币种 CNY，模型填 Unrelated Vendor / USD 并附真实原文；两个错误值仍通过 | 表头值与证据内容一致性核验，缺失、冲突与无法核对时留空并提示 |
| QE-03 | P1 | `wrong_existing_rfq_line`：乙醇被绑定到当前询价中确实存在的甲醇行；服务只检查 ID 属于集合，未发现对象错配 | 对象匹配必须核对产品及规格对应关系；不确定时保留未匹配候选给人工选择 |
| QE-04 | P1 | `duplicate_rfq_candidates`：同一询价行返回两条候选，服务全部保留；前端按顺序赋值可形成最后一条覆盖 | 显式检测重复绑定或冲突候选，分组提示或阻止自动带入，不能默默覆盖 |
| QE-05 | P1 | 代码复核：连续导入 A、B 两份文件时，`sourceFileId` 立即变为 B；B 缺失的日期、备注和明细价格等仍可保留 A 的值 | 明确替换/保留/人工确认策略；保留字段不能未经提示就归到新来源文件下 |

代码依据：[`quote_extraction.py` 的 `_evidence` 及候选生成](../../backend/app/modules/rfqs/quote_extraction.py#L65)、[行 ID 与明细字段处理](../../backend/app/modules/rfqs/quote_extraction.py#L149)、[`quote.vue` 重复导入赋值](../../frontend-design/apps/web-chemicalops/src/views/procurement/rfqs/modules/quote.vue#L173)。QE-05 是静态代码路径复核，未完成浏览器复现，不混入前四个自动探针的分母。

修复优先检查现有系统/阶段提示词与结构化输出 Schema，明确字段证据和冲突表达，再集中补值与证据的统一校验。权限、文件归属、可报价状态和正式写入边界继续由服务端强制检查。避免为 Demo A、某一条报价、特定日期或关键词添加特例。

## 复测方法

离线探针不调用模型。输出路径必须为新文件；发现未通过项时命令返回 1，报告仍完整保存：

```powershell
.venv/Scripts/python.exe scripts/evaluate_quote_extraction.py --output tmp/quote-contract-retest.json
.venv/Scripts/python.exe -m pytest -q tests/test_quote_extraction_evaluation.py tests/test_rfq_quote_extraction.py tests/test_rfq_total_cost.py tests/test_rfq_quote_recommendation.py
```

真实模型模式最多调用三份正常合成报价；扫描抽查可单独运行一次，避免重复计费：

```powershell
.venv/Scripts/python.exe scripts/evaluate_quote_extraction.py --live-model --output tmp/quote-live-retest.json
.venv/Scripts/python.exe scripts/evaluate_quote_extraction.py --live-model --live-ocr --case scan --output tmp/quote-ocr-retest.json
```

真实模式使用已配置模型与 MinerU，关闭重试，单次模型输出上限 3072 Token，模型超时 40 秒，OCR 超时 90 秒。请求失败与没有收到响应时，不标记为已完成真实模型/OCR 评测。当前 Windows 沙箱内最小 `asyncio.to_thread` 调用也会等待，本轮真实调用在沙箱外执行；这项环境现象不作为业务失败证据。

[合成输入目录](quote-extraction-synthetic-v1/) 与 [OCR 调用保留输入](quote-extraction-live-inputs/) 中有正常、缺字段和故意损坏的文件；损坏 PDF 用来验证拒绝路径，不是交付损坏的业务文件。[首次基线](quote-extraction-contract-baseline.json) 与验证后结果均保留，不覆盖旧证据。

[证据清单](quote-extraction-evidence-manifest.json) 保存生产代码版本、依赖版本、原始报告及已归档文件的哈希；清单追加的最终复核记录标明当前复现器及最终报告哈希。报告没有对应二进制归档时会明确记录空的匹配路径，不将相同正文等同于相同文件字节。

真实模型文本抽查的输入由同一生成器即时生成，JSON 保留当时的输入 SHA256；Excel ZIP 元数据可能随生成时间变化，不能将另一次生成文件的字节哈希冒充当次输入。OCR 抽查则同时归档了本次输入字节。

浏览器、真实数据库写入与申请→询价→中选→订单链路仍未验收。
