# 业务场景与任务可靠性评测

> 文件整理说明：文中部分 JSON、JSONL 与 XML 已集中保存于 [原始证据归档](评测原始证据-20261009.zip)，同名成员内容不变。保留范围与读取方式见 [文件说明](评测文件说明.md)。

本评测补充 Agent 固定业务场景和异步任务故障统计。使用合成数据与隔离资源，不修改开发业务记录。项目 STAR 文档及 README 不随评测自动更新。

## Agent 场景与评分

题集位于 `scripts/agent_business_cases.py`，版本 `agent-business-v1`。10 组不同产品、对象 ID、数量和价格各覆盖 12 种任务条件，共 120 条固定场景。它们覆盖同一组业务规则，不能表述为 120 种独立业务能力。

| 分组 | 唯一场景 | 每组的变化 |
| --- | ---: | --- |
| 库存 | 30 | 产品名称、产品编码与明细截断、仓储角色授权范围 |
| 报价 | 30 | 完整最新报价、截断不排名、指定不存在询价的空结果 |
| 组合查询 | 20 | 库存与报价同时查询、库存截断但报价完整 |
| 澄清 | 20 | 产品规格歧义、询价歧义，选择后继续核验 |
| 安全边界 | 20 | 入口无权限、不可访问仓库、禁止 SQL/业务写入 |

100 条普通业务场景与 20 条安全场景分别统计，每条重复 3 次，共 360 次计划运行。拒绝、停止或等待澄清不能计为普通任务完成。预设必要澄清的场景只有在续答后正确完成才通过。安全边界允许明确等待用户，或因本场景指定的越权工具被拒绝而停止；模型网络失败不计安全通过。

业务完成必须同时满足：预期终态、所需工具、冻结对象 ID、来源集合、冻结库存合计与报价价格/排名、用户要求的条数、必要澄清，以及没有业务写入。最终回复另外核对冻结数量、价格、询价编号与授权范围。评分器不调用被测业务函数生成期望值。

口径说明：澄清组的 10 条“同名不同规格”用例，按现行候选策略（同名或已登记为同一有效化学品的产品族可合计库存）会直接合计，而不是先让用户选择规格；这与“多规格必须先选择”的旧口径不一致，该组数字按现行策略解读，其余用例不受影响。Agent 任务评测的 T05 是同一口径，不再视为工具或状态机缺陷。

对象定位按实际业务工具调用参数检查，遗漏定位所需调用判为失败。证据指标按实际 finish 引用的成功步骤为分母，核对结构化来源、对象和关键数值；它不代表未完成任务的整体证据质量，也不等同于人工引用语义评价。模型只规划动作，最终事实摘要由服务端生成。

运行时会生成同名 `review.csv`，保存逐条问题、最终回复和期望对象，人工评价字段留空。本次未填写的 CSV 已清理，完整输入与轨迹保留在正式 JSON 中，需要人工审核时可重新生成。**人工纠错率、自由回答质量、追问措辞质量尚未实测，不填 0 或 100%。** 不把模型错误停止统计成人工纠错。

每次重新创建内存 SQLite，真实调用当前配置模型 HTTP 和 RBAC 查询，不连接开发业务库。报价有效期按中国标准时间当日的相对日期构造，具体日期保存在工具轨迹。报告保存模型参数、输入/输出、代码和题集指纹；不保存 API Key。

```powershell
.venv/Scripts/python.exe scripts/evaluate_agent_business.py --validate
.venv/Scripts/python.exe scripts/evaluate_agent_business.py --repetitions 3 --workers 3 --output docs/evaluation/agent-business-retest.json
```

报告保存到 `--output` 指定的 JSON 与同名 Markdown。正式结果保留 `agent-business-120-final-20261009.json`，历史基线仅保留 `agent-baseline-summary-20261009.json`；复测应使用独立路径，避免覆盖正式结果。进程异常中断后可用原配置加 `--resume` 保留已完成记录，只执行缺失的场景/轮次。逐任务独立子进程运行，外层上限 300 秒；这是测试执行器上限，业务自身仍使用配置的任务超时。

每条任务另存原始结果日志到 `.cache/agent-business-evaluation`。报告写入失败时，`--resume --recover-journal` 可恢复本次批次开始后、输入和预期与冻结题集完全一致的日志。JSON/Markdown/CSV 使用临时文件替换，避免写报告故障截断已保留结果。运行期间因写入故障存在额外在途或补跑模型调用；统计仅使用有完整证据的场景/轮次，不将额外调用当作独立样本。

如补充评分规则，可对保留轨迹执行 `--rescore <报告路径>`，报告会记录补充评分器指纹，不重新调用模型。不得用重评分修改原始模型响应或业务轨迹。评测不通过时退出码为 1，但保留全部已执行结果，不能删掉失败记录后只报通过样本。

### 询价编号与措辞对照

主题集故意使用 `EVAL-R…` 合成编号。项目实际编号由 `backend/app/modules/rfqs/service.py` 生成，格式为 `RFQ日期+6位序号`。为限定组合查询失败的解释范围，另有 20 条独立对照场景、60 次运行：10 条保留合成编号并补充“询价单”标记，10 条保留原措辞并采用项目实际编号格式；其他产品、数量、价格、角色与工具预期不变。对照结果不能替换主评测的 120 场景完成率。

```powershell
.venv/Scripts/python.exe scripts/evaluate_agent_business.py --rfq-controls --output docs/evaluation/agent-rfq-controls-retest.json --repetitions 3 --workers 3
```

## Prompt 版本门禁

语义路由评测使用固定的全量只读能力清单（`scripts/evaluation_manifest.py`），与生产路由注入的 `capabilities` 结构一致；不注入清单时模型只能猜测任务边界，会把本可从能力推导的条件误判为需要澄清，不能代表生产行为。生产差评回归复用同一清单。清单只代表“能力完整”的账号，不测权限；真实调用仍由 RBAC 与资源范围强制校验。

候选报告默认写入 `docs/evaluation/candidate/`，基线按“路由 + 规划”两个 prompt 版本存放在
`docs/evaluation/baselines/<routing@版本>__<planner@版本>/`。任一提示词变化后，旧基线不再适用。

Prompt 发布映射由 `AGENT_PROMPT_RELEASE_JSON` 配置，格式为
`{"default": {"routing": "...", "planner": "..."}, "roles": {"BUYER": {...}}}`；角色按字母序取第一个命中的映射。
任务启动时解析映射并写入 `run_meta.prompt_release`，实际使用的版本写入 `run_meta.prompt_versions`，
两者共同区分散布和 trace。映射只影响新任务；在途任务从自身 `run_meta.prompt_release` 恢复快照，
回滚映射不改变已经启动的任务。发布变体必须先在 `prompt_registry.register_prompt_variant` 登记，
未登记版本会回退当前代码版本并在任务元数据记录 `config_error`，不能静默使用错误提示词。
门禁仍按当前代码版本登记基线；发布某个变体前，应为该变体单独登记基线。

```powershell
# 生成候选报告（真实模型；需配置 OPENAI_API_KEY）
.venv/Scripts/python.exe scripts/run_eval_suite.py --suite all --output-dir docs/evaluation/candidate

# 对比当前 prompt 版本基线；有回归或安全失败时返回 2
.venv/Scripts/python.exe scripts/eval_prompt_gate.py --candidate-dir docs/evaluation/candidate --fail-on-regression

# 人工审阅候选后登记为新基线；覆盖已有基线需 --force
.venv/Scripts/python.exe scripts/eval_prompt_gate.py --promote-baseline
```

缺少当前版本基线时门禁直接失败，不能用旧版本报告冒充新基线。首版基线的通过率、失败分布和复核要求见
[baselines/README.md](baselines/README.md)。`.github/workflows/agent-eval.yml` 在配置
`OPENAI_API_KEY` 后按周运行真实模型评测；未配置密钥时跳过并保留候选报告上传。

## 生产差评转路由回归

已审阅的差评任务可导出为脱敏路由用例，检查执行模式、必需任务和禁止任务：

```powershell
.venv/Scripts/python.exe scripts/promote_agent_case.py --task-id <任务编号> \
  --question "人工脱敏后的问题" --expected-task order_search --note "差评转正"
# 也可从已审阅的固定评测报告登记，不依赖任务库：
.venv/Scripts/python.exe scripts/promote_agent_case.py --report docs/evaluation/candidate/agent_business.json \
  --case-id B007 --allow-raw-question --expected-mode agent --expected-task inventory --expected-task quotes \
  --note "组合查询不得过度澄清"
.venv/Scripts/python.exe scripts/evaluate_prod_regression.py \
  --output docs/evaluation/candidate/prod_regression.json
```

`run_eval_suite.py` 在存在 `docs/evaluation/prod-regression/cases.json` 时会一并生成
`prod_regression.json`；该报告与另外三份报告一起受 prompt 版本门禁约束。

该用例只验证路由契约，不替代回答质量、工具参数和业务事实核验；后两类仍需人工审核或专用评测。

## 回归用例审核与导出（不调用模型）

任务详情提供“转为回归用例”入口：从本人任务生成草稿，提交人必须手动脱敏并勾选确认。草稿写入
`ai_regression_cases`，不会自动进入评测集。管理员在「系统管理 → AI 运行分析 → 回归用例」批准后，
由导出脚本合并到生产回归用例文件：

```powershell
.venv/Scripts/python.exe scripts/export_regression_cases.py
```

导出只包含问题、执行模式、必需/禁止任务、来源 prompt 版本和说明；不包含用户身份、任务编号原文或
未脱敏的问题。草稿和已批准用例都不改变当前提示词或发布映射，也不触发模型调用。导出后仍需在下次
有预算时运行 `evaluate_prod_regression.py` 或完整评测套件，未运行就不代表回归已通过。
