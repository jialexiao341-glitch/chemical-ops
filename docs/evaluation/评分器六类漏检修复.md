# 报价评分器六类漏检修复

> 最终后端全量回归：**1644 passed、0 failed、11 skipped**，共 1655 项。v2 门禁 CLI 复核通过，5 个文件及 12 条数字关联样本验证完成。详见[结构化结果](quote-oracle-remediation.json)。11 个跳过项仍为未启用的隔离 MySQL、Redis、真实 MinIO 和 Worker 故障演练专项，不计为通过。

## 结果与范围

修复对象是固定合成样本的评测评分器，不修改生产报价的筛选、排名、金额计算、权限或定标行为。原始漏检证据保留在[独立核对记录](新版基线独立核对.md)和对应 JSON，不覆盖历史结果。

现在业务场景评分器 `evidence_correct` 与旧任务评分器 `check_evidence` 共用 `scripts/evaluate_agent_tasks.py` 中的 `quote_evidence_correct`，集中检查同一套独立预期。该函数仅适用 `evaluation_db` 固定样本，不能作为任意业务报价的生产校验规则。

## 六类校验

| 类别 | 新增校验 |
| --- | --- |
| 总行数错误 | 全范围总数固定为 9；完整结果 9 行，截断结果按请求限额保留行数，总数仍为 9；截断标识也须一致 |
| 含税口径错误 | 15 必须明确未税、16 必须未知，其余为含税；校验税率、单位、型号、数量、独立价格和组内排名，不能混淆口径 |
| 币种错误 | 6 必须为 USD，其余为 CNY；行级币种和成本币种均与固定原始样本一致 |
| 重复行 | 同时核对行数、唯一 ID 集合和来源数量，拒绝重复业务行、重复来源或二者一起重复；仍验证来源资源和询价归属 |
| 虚构总成本 | 本夹具运费未知，必须保持 `complete=false`、总成本及运费/运费税为空；商品金额和商品税另用 Decimal 独立计算并核对 |
| 虚构推荐 | 必须为 `NO_RECOMMENDATION`，候选报价、候选供应商、推荐币种和推荐金额均为空；不能只保留状态而夹带候选或金额 |

缺少成本/推荐字段或数值字段格式错误时，评分器判定不通过，不因异常结构中断整批评测。完整与截断结果、1/3/10 倍价格变体，以及两个评分入口均纳入测试。

## 测试证据

新增 [反例回归用例](../../tests/test_quote_evidence_oracle.py)：6 个评分器/样本组合，每组包含 1 个正常结果及 21 个单独篡改变体，共 132 项。

- 修复前：**104 failed、28 passed**，证明旧评分器确实漏过这些反例。
- 修复后：132 项全部通过；另有 140 个业务/控制场景的独立数字 oracle 通过，合计 **272 passed**。
- 再次生成正常报价并逐项执行 21 种篡改：正常结果被接受，21 种错误全部被拒绝，见[结构化复测证据](quote-oracle-remediation.json)。

复现命令：

```powershell
.venv/Scripts/python.exe -m pytest -q --tb=short tests/test_quote_evidence_oracle.py tests/test_business_evaluation_metrics.py::test_all_fixtures_and_independent_numeric_oracle
```

评分器使用固定预期与独立 Decimal 公式，没有调用被测生产过滤、排名或成本函数生成正确答案。合成评测通过仍不代表真实模型质量或真实采购效果。浏览器验收继续后置。

## 已授权的新版基线迁移

6 类漏检修复后，原门禁下全量为 **1639 passed、1 failed、11 skipped**，唯一失败为旧 manifest 完整性校验。继续执行用户此前“落实新版”的授权，已新增 [v2 清单](offline-guards-v2-manifest.json)，保留 v1 原样，并将校验器固定切换到 v2 静态哈希锚点。

v2 覆盖原始数字题集、120 个业务场景、业务场景评分器与造数代码、共享 SQL/RBAC 夹具、旧版任务评分器，共 5 个文件。12 条数字关联样本与 120 个业务场景题目不变，20 个 RFQ 控制场景继续保留。此次只按已核对的当前内容建立基线，运行时没有自动重算或接受漂移的路径。

摘要计算仅把 CRLF 转为 LF；字段、业务值、空格、JSON 顺序、尾部空行等其他变化仍改变哈希。新增逐文件篡改检查，要求错误消息准确指向被篡改文件，防止测试仅因别处校验失败而误算通过。正常基线和仅换行符变化应通过；5 个受保护文件或 manifest 附加一行均须失败。

v2 门禁、评分器反例和 140 个数字 oracle 联合回归为 **280 passed**。旧版门禁的历史失败仍保留在原记录中，不改写为通过。
