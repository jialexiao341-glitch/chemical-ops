### Agent 普通问答后的指代查询

使用采购员账号与已配置的 `deepseek-flash` 模型，先在普通聊天询问“丙酮是什么，有哪些常见用途？”，再追问“它还有多少库存？”和“它的供应商报价是多少？”。模型均调用 `catalog.search_products(keyword="丙酮")` 并返回四个规格，确认选择后没有复用历史数值或业务证据，而是重新检索本轮业务数据。库存任务选 `AR-5L/桶` 后返回当前采购员可访问范围无库存记录，并说明不能据此推断企业没有库存。报价任务在同规格下没有本人可见询价时返回无匹配；另在新普通问答会话重复报价流程，选择有本人可见询价的分析纯规格后找到 `RFQ-26001`，读取三家最新报价 72、74、76 CNY/升，注明报价按未税单价、不同供应商型号不排序、不推断成交、不自动选择供应商。见 [指代解析真实模型结果](Agent普通问答指代验收-20261004.json)。这些用例验证了普通问答上下文关联、产品消歧和新鲜业务证据路径，不代表总体回答质量指标。

运行时隔离回归 28 项通过，其中新增库存和报价两条用例分别断言普通问答对话被装入上下文、本轮工具结果用于作答、虚构历史数值未泄入结果。

### 浏览器期间发现并修复

质量资料表单通过已有请求客户端提交 FormData 时意外携带 JSON 默认请求头，后端 422 并提示表单字段缺失。上传函数现显式声明 multipart/form-data，沿用项目现有附件上传模式；修复后浏览器提交、真实对象下载与内容哈希核对均通过。前端沿用原供应商列表、弹窗、日期选择器、下拉框和行操作模板，没有新建视觉模板。

## 原自动化回归

1. 供应商和内部财务留言接口只检查原字符串长度，纯空格/换行通过校验后被保存为空字符串。共享请求模型现先去除首尾空白，再校验至少一个字符，纯空白请求返回 422；双方各一条回归验证。
2. 供应商公共列表继承的分页器提供 200 条/页，而六类门户列表接口上限为 100。保留现有分页模板，将选项限制为 10、20、30、50、100；六类接口验证 100 合法、200 返回 422，空结果与分页响应正确。

## 未覆盖与限制

- 浏览器可访问开发前端；本轮逐页操作主要覆盖单据筛选、菜单、弹窗、报价提交、日期、发货、文件上传/下载和对账留言/确认，未覆盖六页全部键盘/窄屏/主题、导出或每个状态组合。
- Agent 本轮完成了多候选后的规格选择与库存/报价查询；库存所选规格在采购员当前仓库权限范围内无余额记录。报价有数据路径验证了三家明细与最终回答一致；尚未覆盖单候选、复杂指代、其他授权仓库或整体模型回答质量评估。
- 11 类非管理员演示角色均已浏览器登录并核对侧边栏顶层分组；供应商、质量、主数据和财务页面有代表性子页面/按钮证据，但其余角色的全部三级页面与详情内操作矩阵尚未逐页覆盖。系统管理员角色亦未切换浏览器验证。
- MinIO 网络中断、超大文件、并发发货竞争、后端全量测试及生产配置未验收。供应商流程数据和质量结论均为本地模拟材料。pytest 集合重跑受 finance_clerk 测试凭据与本机 development 数据库不匹配影响，认证 401；需修复测试环境凭据后再补跑，不重置演示账号密码。
