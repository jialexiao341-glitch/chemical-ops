# 发票行匹配第二阶段回归

## 本阶段行为

新版对账单的发票由财务人员人工匹配到保存版对账行。可先保存有差异的草稿，提交前必须满足：对账已确认、来源未变化、当前版本匹配完整、不含税和税额分别等于票面合计、各行及整单累计不超应付。其他有效发票没有匹配时不能猜测额度归属。

税额比例或尾差与对账行不同必须填写处理说明；系统不自动修改金额、不自动吸收尾差。提交和核验会重新检查当前依据和占用额度。复核人必须与提交人及匹配人不同；每次匹配追加版本，提交、驳回、核验和作废写入审计。

驳回释放占用，重新提交时再次校验。草稿或驳回票可填写原因作废；作废后保留历史匹配。已核验发票不能直接作废，本阶段未实现红字和冲销。

财务差异分析增加票行匹配依据和各对账行已核验开票金额；只将实际匹配的有效发票计入行汇总。付款仍按单据汇总。核查清单新增各发票条目，沿用指派、发现记录和双人复核；已复核后修改负责人或说明必须先重开。发票匹配或有效状态变化自动重开该订单已有处理结果，并追加原因。

历史对账版本 0 沿用原单据级发票核验，不猜产品行归属，页面明确标记历史边界。

## 模拟材料

新增六组独立链路、八张模拟发票，使用 `PO-SIMINV-` / `DEV-SIM-` 编号。重复运行样本脚本不新增重复记录、不覆盖处理状态。说明和 CSV 见 [发票样本](../invoice-samples/README.md)。这些样本只验证开发流程，不代表真实采购、质量验收、税务开票或业务效果。

## 当前范围

每张发票只对应一个对账单，可以匹配其多个产品行；不支持一张发票跨对账单。未接入发票文件识别、税务验真、付款行分配、已核验发票冲销及部分质量放行结算。差异核查的“已复核”是人工处理记录，不自动变更正式应付或付款状态。

## 页面复查

沿用现有 AntDV/Vben 组件、主题色、字号及间距，不引入另一套设计令牌。复查后的修改：

1. 根据权限隐藏录入、核验及驳回按钮，避免展示用户无法执行的动作。
2. 历史匹配只读，不将当前剩余额度当成历史余额；已复核的差异说明和负责人禁用编辑。
3. 金额输入提供行级可访问名称；抽屉在窄屏使用全宽和表格横向滚动，加载失败提供重试。
4. 保存中锁定抽屉，失败保留输入；税额或尾差显示明确的处理说明要求。
