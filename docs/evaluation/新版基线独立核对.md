# 新版基线独立核对

> 后续已修复本记录发现的 6 类评分器漏检，并按用户授权落实 v2 基线；门禁、正常/反例与数字 oracle 联合回归共 280 项通过，详见[六类漏检修复](评分器六类漏检修复.md)。下文保留修复前的独立核对结果。

## 结论

用户已同意采用新版。本轮先核对业务预期和评分器的反例拦截能力，没有切换门禁、重算冻结清单或创建 v2 manifest。

报价样本的 **9 行证据及单价组内排名预期正确**，但当前业务评分器存在 **6 类已证实的漏检**。应先补齐校验并通过反例测试，再冻结新版；不能把“现有 142 项回归通过”作为答案完整正确的证明。

原始样本、独立计算结果及反例检查见[结构化核对证据](baseline-independent-audit.json)。这是合成数据、确定性规则的离线核对，不代表真实模型或业务效果。

## 独立计算

读取评测隔离数据库中原始报价、版本、状态、有效期、供应商和单位状态，用独立 Python 规则重新筛选和分组，未调用生产过滤、排名或成本辅助函数生成预期。

16 份原始报价中，排除以下 7 份：

| 报价 ID | 排除原因 |
| --- | --- |
| 1 | 同供应商有更新版本 2 |
| 4 | 已过期 |
| 10 | 同供应商已有更新版本 11；新版撤回后也不能恢复旧报价 |
| 11 | 已撤回 |
| 12 | 报价日期在未来 |
| 13 | 供应商停用 |
| 14 | 单位停用 |

剩余证据 ID 为 **2、3、5、6、7、8、9、15、16**。报价 2 和 3 同为 CNY、千克、税率 13%、含税、型号 A，有效期明确；单价分别为 10 和 8，因此报价 3 排第 1、报价 2 排第 2。

其余各行保留证据但不排名：5 缺有效期，6 为 USD，7 使用升而非请求的千克，8 缺税率，9 为型号 B，15 为未税，16 缺含税口径。不同明确口径可以在同口径候选足够时形成各自的组；本样本这些候选不能与 2/3 混排。

另外，业务评测夹具没有登记运费，不能把有单价排名理解为已有完整总成本或可推荐中选。当前正确结果应为 `NO_RECOMMENDATION`。工具层另一个夹具为报价 2 提供了运费，因此其 121.20 元总成本预期属于不同夹具，不能移植到这里。

## 评分器反例检查

先确认正常结果能通过，再复制结果逐次只修改一项，检查 `evidence_correct` 是否拒绝。

| 故意制造的错误 | 实际被拒绝 |
| --- | --- |
| 单价改为 999 | 是 |
| 删去一条报价 | 是 |
| 报价 2 错标为第 1 | 是 |
| 来源父对象改为其他询价 | 是 |
| 总行数由 9 改为 7 | **否** |
| 报价 15 的未税改为含税 | **否** |
| 报价 6 的 USD 改为 CNY | **否** |
| 重复追加已有报价行 | **否** |
| 运费缺失时虚构完整总成本 | **否** |
| 虚构可推荐中选结论 | **否** |

当前评分器主要检查 ID 集合、部分数量/价格、排名与来源，没有完整核验上述字段；集合比较也会吞掉重复行。这些是评分器漏检，不能据此断言生产工具当前已经生成这些错误。

## 后续冻结前的检查条件

补齐总数/唯一性、税费/币种事实、成本完整性和推荐结论校验，为上述 6 类错误保留独立反例。正常的完整/截断结果应通过；改错结果必须失败。之后才适合执行用户已授权的 v2 基线迁移。

本轮复跑 140 个业务样本/控制场景的数字 oracle，以及工具层报价边界与截断用例，共 **142 passed**。这些正例回归与上述反例漏检应共同解读，不合并为“新版基线已验收”。浏览器验收继续后置。
