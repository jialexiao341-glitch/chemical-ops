# 智能体查询隔离与结构化输出验证

## 本次实现

- 查询计划与意图理解使用 Pydantic 模型生成严格 JSON Schema，禁止额外字段；数据集、指标、时间字段、分组与筛选字段来自白名单。模型返回后使用 `model_validate_json(..., strict=True)` 验证，再执行当前权限及数据范围校验。
- QueryPlan 九个槽位的类型、枚举、可空、必填、含义与数据集适用范围直接写入接口 Schema；filters 的 field/operator/value 独立定义。字段说明和目录从规划提示词移出，由 Pydantic 字段生成；[实际 Schema 快照](query-plan-schema.json)可直接查看。字段类型和枚举由 Schema 约束，跨字段组合及当前权限继续由服务端验证。
- 当前 DeepSeek 结构化请求使用 Responses 接口；普通回答沿用原接口。日期使用 Schema 正则限定外形，Pydantic 校验真实日期；截断响应拒绝执行，不静默降级为无约束模型输出。
- 单项条件修改将已还原指代的子任务问题传给计划器，避免直接用“修改第二项”生成计划。
- 历史查询在展示及进入理解模型前，按当前用户重新核验权限、查询结果、截断状态和来源记录身份。待补充任务也重新核验已有工具证据；失效时清除业务来源与相关模型记忆。
- 补齐已批准未询价采购申请的部门/申请人范围；供应商聚合异常沿用业务范围规则；订单追溯中的申请、询价、报价、验收及库存批次遵循各自范围。
- 多意图结果按子任务复用现有查询来源及工具过程组件，显示对应结果与来源。
- 批量查询通过 SSE 返回各项状态、已完成数及已完成证据；沿用原任务组件提供取消入口。整组规划及执行使用现有 `agent_task_timeout_seconds` 总时限，超时保留成功项并标记未完成项。
- 断开流或主动取消时停止后续项，保存部分结果和取消终态。新会话先保存后返回进度，避免取消后读取历史短暂报无权访问。前端会话切换和取消后忽略迟到响应。
- “重试未完成项”仅从本人最新保存批次恢复失败、阻塞及取消项；成功项和待补充项复用前重新核验当前权限、范围和证据，失效则拒绝重试并要求重新查询。文档摘录改变或解析状态撤销也不可复用；修改附件或条件需要重新发起查询。
- 技术研发角色仍不开放通用库存读取。

## 自动化验证

相关十一组测试合计 **189 项通过**。包含跨用户会话、跨仓库统计及来源、权限撤销后的历史和模型上下文，以及非法字段、类型、日期、日期关系、槽位 Schema 元数据和截断输出测试。执行体验测试覆盖总超时、取消后部分结果持久化、仅重试未完成项、跨用户重试拒绝、权限变化拒绝复用和文档摘录/解析状态失效。

前端类型检查通过。存在一项第三方 Starlette/AnyIO 弃用告警。
