# 报价文件解析缺口修复与复测

本轮落实[专项评测](报价文件解析专项评测报告.md)的 QE-01～QE-05。历史报告和失败结果保留；本轮新增证据不覆盖原有文件。

| 缺口 | 当前行为 |
| --- | --- |
| QE-01 明细依据 | Prompt 与严格输出 Schema 要求逐字段短引句；字段引句须位于本条真实原文内。统一校验数值、日期、币种、含税口径和文本词面支持，缺少依据则清空并提示。 |
| QE-02 表头不一致 | 值须与真实表头引句相符；不一致清空，不擅自纠正为另一个值。 |
| QE-03 询价错行 | 名称和请求规格须唯一匹配；原文规格或供应商型号可与请求规格精确对应。模型 ID 还须与该唯一对象一致，否则解除绑定。 |
| QE-04 重复与冲突 | 完全相同候选去重；按服务端核验的对象归组检测多候选，包含模型未填或错填 ID 的候选，冲突时全部解除自动绑定。前端也拒绝重复绑定覆盖。 |
| QE-05 重复导入 | 成功解析后整表替换；缺项清空，报价单位及 MOQ 单位不沿用询价或旧文件的单位，供应商重新选择。已有输入时确认替换，取消或解析失败保留原表单；关闭重开后的迟到结果失效。解析中禁止编辑、重复解析和提交。 |

前端沿用原报价弹窗、表格、选择器和项目已有确认弹窗，仅调整状态与带入逻辑。

[本轮证据清单](quote-extraction-remediation-evidence.json)记录最终源码、报告与输入文件哈希，并注明采集时点；真实模型抽查的输入均已找到字节一致的归档。

## 验证证据

- 离线契约评测 **12/12**：[最终检查](quote-extraction-contract-release-check.json)。模拟模型输出，仅验证解析与服务端契约，不能作为真实模型准确率。
- 真实模型正常格式抽查 **3/3**：CSV、文本 PDF、Excel 的[复测输出](quote-extraction-live-remediated-retest.json)及[实际输入归档](quote-extraction-remediated-retest-inputs/)。
- 真实 OCR＋模型扫描件抽查 **1/1**：[输出](quote-extraction-live-ocr-remediated.json)及[实际输入归档](quote-extraction-ocr-remediated-inputs/)。
- 前端替换纯函数与报价弹窗组件 **8 项通过**，覆盖整表替换、重复绑定、未知单位、零值与未税口径、确认取消、解析失败、关闭重开后的迟到解析/加载响应，以及解析期间编辑/提交/重复上传防护。
- 后端字段抽取、评测器、报价总成本与建议、文件解析及 MinerU 相关回归 **55 项通过**；前端 `vue-tsc --noEmit --skipLibCheck` 通过。

真实模型复测前曾出现正常格式仅 1/3 通过的[失败报告](quote-extraction-live-remediated.json)。[Excel 诊断输出](quote-extraction-live-xlsx-diagnostic.json)显示模型将税率写为 `13%`，且将与请求规格一致的供应商型号留为未绑定。随后在 Schema 和 Prompt 中明确税率纯数值、型号与规格的匹配契约，未放宽服务端证据校验；再次运行三种格式全部通过。首次 Excel 失败未保存原始模型输出，不能断言其具体原因与后续诊断相同。

新契约将错误表头值、错误询价 ID 以及缺少请求规格依据的对象预期设为 `null`；这是安全拒绝契约，服务端不代替模型猜测或纠错。独立人工标注的正常字段预期保持不变。首次复测的 11/12 结果也保留于 [中间报告](quote-extraction-contract-remediated.json)，其唯一差异是缺规格时的绑定预期；最终契约明确该情形应解除绑定。

独立审查发现冲突检测最初只统计模型已填 ID 的候选，已改为服务端对象归组；新增第二条候选 ID 为正常、空值和错误值的参数化回归，观察到失败后完成修复。

## 验证范围和下一步

以上真实抽查仍是同一份英文单行合成报价的四种文件表现，不是四个独立业务场景。词面证据校验不能证明任意上下文下的完整业务语义，仍须人工复核；未覆盖真实供应商复杂表格、中文扫描件和长文件。

文件扫描、正式上传、询价读取及数据库写入在评测中隔离；没有创建正式报价、中选或订单。前端组件测试使用模拟接口及基础组件替身，禁编辑的动态断言覆盖表头控件，明细行控件的禁用属性经静态复核；尚未完成浏览器验收。下一步为申请→询价→报价复核→中选→订单草稿→提交审批的真实业务链路验收，并统一执行浏览器验收。
