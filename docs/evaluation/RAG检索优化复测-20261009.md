## 改动与原因

1. 按查询字段选择桥接候选，再应用每个 CAS 最多 8 章的限制。原先直接按章节顺序截断，MSDS 第 9 节可能在进入排序前就被排除。
2. 结合中英文字段标签覆盖率、明确请求的文档类型及 MSDS 第 9 节结构信息排序，降低网页导航、供应商链接等无关内容挤占结果的影响。标签匹配仅检查实际注入模型的前 1500 字。
3. 补充“安全资料”“产品资料”“产品技术资料”等来源表达，保留单来源约束；跨来源比较保留每种明确请求来源的候选。
4. 评测支持独立输出与冻结题集输入，记录题集、检索器及评测器指纹。检查点使用临时文件写入后替换，避免写入中断破坏已有结果。

实现使用通用字段及文档结构，没有将题目编号、预期数值或具体章节 ID 写入生产检索规则。排序权重在本题集诊断后确定，因此本轮属于固定集回归及调优，不是独立留出集评估。

## 回答验证与边界

优化后完成全部 200 题回答验证，其中 174 题使用模型回答，26 题使用无证据或目标澄清规则回复。最终结果中模型生成错误为 0。执行中曾发生一次 Windows 检查点文件写入错误；改为先写临时文件再替换后，从已有结果继续完成，未改变评分条件或选择性剔除失败题。

| 自动检查 | 结果 | 判定范围 |
| --- | ---: | --- |
| 可回答题预期事实匹配 | 149/149 | 预期数值或分子式出现在回答中 |
| 事实匹配且完整证据召回 | 149/149 | 同时满足预期事实匹配及 gold 章节全部进入前六条 |

## 复现与产物

在项目根目录运行：

```powershell
.venv/Scripts/python.exe scripts/evaluate_rag.py --suite mixed200 --gold docs/evaluation/rag-20261009-before_cases.jsonl --retrieval-only --force --output-prefix docs/evaluation/rag-rerun
.venv/Scripts/python.exe scripts/evaluate_rag.py --suite mixed200 --gold docs/evaluation/rag-20261009-before_cases.jsonl --output-prefix docs/evaluation/rag-rerun
.venv/Scripts/python.exe -m pytest tests/test_doc_rag.py tests/test_doc_cleaning.py tests/test_rag_evaluation.py tests/test_ai_evaluation.py -q
```

首次重建失效 ID 快照时，可以使用独立输出前缀及 `--rebind-missing-evidence`；内容改变或匹配不唯一会拒绝继续，不能借此替换预期事实。复跑当前代码不能重新生成旧实现的基线，应保留本轮基线文件。独立实验应使用新的输出前缀，避免复用其他实现的检查点。

- `rag-20261009-before_cases.jsonl`：本轮冻结题集。
- `rag-20261009-before_evidence_mapping.json`：3 道题的 ID 重绑定及内容指纹。
- `rag-20261009-before_summary.json`：优化前指标及分类摘要；按用户要求清理了优化前逐题结果，保留冻结题集与证据映射。
- `rag-20261009-after_results.jsonl`、`rag-20261009-after_summary.json`：优化后逐题检索、回答及摘要。
- `rag-generalization-regression-20261009.xml`：保留最新关联回归结果，共 65 项通过，包含本轮的 60 项验证及后续题集与评分边界检查；覆盖向量故障降级、网页内容挤占、多来源覆盖、单来源约束和证据重绑定拒绝条件。被最新结果覆盖的中间 XML 已清理。

检索耗时使用批量缓存后的 embedding，排除了 embedding 服务耗时，不能作为线上端到端响应时延。Recall、MRR 和 nDCG 衡量章节检索，不能替代回答质量和业务效果。
