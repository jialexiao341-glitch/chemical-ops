# 文档智能中心首期实施计划

设计依据：[文档智能中心首期设计](../specs/2026-10-28-document-center-design.md)。

1. 后端先编写三类来源的权限、筛选、分页及引用测试，覆盖仅有文件权限、仅有业务权限、权限撤销、跨对象共享文件、缺失文件和失败状态。确认测试在实现前失败。
2. 实现只读聚合服务与接口：按业务对象及文件双重授权过滤后再分页；质量报告复用已保存核对快照的授权读取；报价和发票无持久化候选时明确返回未保存依据。不得把通用文件解析状态当成业务解析结果。
3. 使用现有列表模板接入类型和关键字筛选、分页、统一引用展示与跳转；质量验收页增加受现有权限约束的报告复核定位，其他类型复用已有详情跳转。
4. 运行后端针对性测试、相关权限及三类原有业务回归，运行前端针对性测试和类型检查；核查列表样式与现有模板一致。记录未执行的浏览器验收及真实文件/模型限制。

重点复核：文件上传者也不能绕过业务范围；权限过滤必须早于分页和总数计算；相同文件可能关联多个业务对象；质量报告快照与关联文件必须匹配；旧报价和发票没有持久化证据时不能伪造原文或页码。

## 剩余工作：业务解析记录和授权分页

1. 新增独立的业务解析尝试记录及迁移，记录类型、来源业务对象、发起人、阶段状态、可公开的失败类别、成功后文件引用与经过服务端核验的候选和原文位置。历史没有记录的文件仍显示依据未保存，不以重新解析结果冒充历史。
2. 在报价、发票和质量的业务解析入口完成现有权限和对象范围检查后创建尝试，成功后关联文件和候选快照，失败时记录安全的失败类别；扫描拒绝、权限失败及业务校验失败不应被伪装成解析失败。明确中断恢复和数据库事务，避免失败处理提交未授权业务数据。
3. 读取时分别重验业务对象及文件权限，用户确认后的正式值与原始候选分开呈现；引用不可被客户端构造或覆盖。发票解析起点是对账单，引用须验证后续发票仍属于该对账单；报价须验证后续报价仍属于来源询价单。
4. 复用现有数据范围与文件权限规则构建数据库可执行的可见条件，在数据库过滤后统一排序、计数、分页；覆盖私有文件、共享附件、上传者、质量负责人、多业务关联、撤权及无文件。不要以先分页后逐条过滤或放宽文件权限代替完整语义。
5. 对成功、解析失败、模型提取失败、无依据、撤权、用户取消和重复提交进行真实接口与数据库回归；为分页构造超出单页的混合权限样本，核对每页及总数，并测量查询次数。浏览器验收仍按既定策略延后。
