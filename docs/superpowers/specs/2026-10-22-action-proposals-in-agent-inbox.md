# Agent Inbox 动作提案汇总与处理

## 目标

在现有 Agent Inbox 汇总当前用户待确认的采购申请新建/修改/提交提案和询价草稿提案。用户可在统一详情中检查差异、证据、阻塞项和有效期，继续使用既有提案修订、确认、取消接口，并识别不可继续操作的提案及其返回原单据入口。

## 现状与约束

- `/ai/tasks` 当前只查询本人 Agent 任务，`inbox_only=true` 过滤等待补充或失败任务。
- `/ai/action-proposals` 已提供提案创建、PATCH 修订、确认和取消能力；提案模型保存 `action_type`、资源引用、版本、快照、差异、证据、阻塞项、权限码、有效期和状态。
- 动作提案当前没有列表/详情读取接口。确认时会再次校验用户权限、提案版本、过期时间和领域资源快照。
- 前端工作台已有动作提案确认流程；新 Inbox 应复用其接口和确认交互契约，不创建第二套执行接口。
- 页面继续复用现有 AI 任务列表的 VXE Grid、工具栏、Modal、按钮及项目既有样式，不另造视觉模板。
- Inbox 仅汇总 `purchase_request.update_draft`、`purchase_request.submit`、`rfq.create_draft` 三类提案；采购申请草稿创建保留现有工作台确认流程。
- 不修改 `docs/项目介绍与成果（STAR）.md`，不自动修改 README。

## 用户流程

1. 打开 `/ai/tasks` 的 Agent Inbox，看到待处理 Agent 任务和待确认动作提案；仍可切换全部任务。
2. 提案列表显示提案类型、关联单号（询价草稿显示来源采购申请单号）、状态、过期时间，并提供查看操作。
3. 查看提案详情时呈现差异、证据、警告、阻塞项、风险级别及有效期。仅在提案仍有效且当前账号有对应写权限时提供确认、修改和取消操作。
4. 用户修改后必须展示服务端返回的新预览版本，再允许确认；确认和取消继续带 `confirmation_id` 与 `preview_version` 调用现有接口。
5. 已过期、资源快照变化、权限失效的提案以不可执行状态显示，并关闭写操作。资源仍可访问时提供返回原单据链接；询价草稿指向其来源采购申请，因为草稿尚未创建询价单。

## API 与状态语义

- 在 AI 模块新增本人动作提案分页读取接口，支持 `inbox_only` 和分页；结果仅包含当前登录用户自己的提案。详情读取也必须校验所有权。
- 列表/详情响应在现有预览字段上补充创建时间及可展示的单据编号/原单据路由信息；不返回 `payload`、资源快照、权限码或幂等键。
- 状态以服务端为准：`PENDING`、`EXECUTED`、`CANCELLED`、`EXPIRED`、`INVALIDATED`。读取时将已过期的 `PENDING` 规范为 `EXPIRED`；若领域当前状态或快照与提案不符，规范为 `INVALIDATED`。
- 当前用户失去动作所需权限时，响应提供独立的 `availability`（`AVAILABLE` / `PERMISSION_REVOKED` / `RESOURCE_UNAVAILABLE`），不把权限变化错误写成提案永久失效。资源失去可见性时隐藏其路由和编号，避免泄露。
- 询价草稿确认需要询价写权限和供应商读取权限；PATCH 修订可提交字段增量，服务端仅合并 allowlist 字段并保留其余执行参数。响应只提供可编辑字段投影，不返回执行 payload。
- `requires_user_confirmation` 仅当状态为 `PENDING`、未过期、资源快照仍有效且当前有权限时为 true。
- 读取接口不得执行领域写操作。对提案继续确认时，现有确认端点仍须执行最终权限、过期、版本和资源校验；失败返回既有业务错误。
- `rfq.create_draft` 的原始业务入口是来源采购申请；采购申请新建尚无已存在原单据时不提供原单据跳转。采购申请修改/提交提案返回采购申请详情入口。

## 安全与一致性

- 仅当前用户本人可列出和读取其提案；接口保留 AI 工作区读取权限门槛。
- 每项提案分别按执行所需权限集合评估可用性；不因 Inbox 有读取权限而授予写权限。
- 派生状态只依据已保存的提案与服务端当前资源验证结果，不采信客户端传入状态。
- 列表中不可见资源不得通过编号、证据、路由或错误消息暴露其存在或内容。
- 确认、取消、修订继续使用现有事务、版本号和提案接口，任何新读取逻辑不绕过最终执行检查。
- Inbox 的资源快照复核使用无锁读取；最终确认仍在既有事务中使用行锁并再次复核。

## 验收标准

- Inbox 能同时区分任务和动作提案，并可查看每条提案的单号、状态和过期时间。
- 提案详情完整呈现差异、证据、警告与阻塞项；有效提案可沿用已有模板进行确认、修订和取消。
- 过期、资源变化和权限撤销在列表/详情明确可辨，且不能触发确认/修订/取消。
- 可访问的关联单据可跳转；不可访问的资源不泄露单号或链接；询价草稿跳回来源采购申请。
- 现有 Agent 任务 Inbox、工作台提案确认流程及其他 AI 路由行为保持兼容。
- 验收采用有代表性的已有提案样本，并覆盖所有者隔离、权限变化、资源变化和过期状态。
