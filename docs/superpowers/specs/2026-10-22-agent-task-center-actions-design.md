# Agent 任务中心操作入口设计

## 目标

让用户能够从 AI 任务中心处理本人尚未完成的只读 Agent 任务，不必回到原聊天寻找任务。继续和取消按 `task_id` 调用现有服务端接口；重试从原始查询创建新任务，不复用旧任务的执行结果。服务端继续负责任务归属、状态、revision、当前权限和证据校验。

## 范围

- `WAITING_INPUT`：允许打开详情后补充问题并继续；保留已有候选选择能力。
- `RUNNING`：允许取消；请求期间锁定对应行操作，完成后刷新任务记录。
- `FAILED`：允许以首次用户查询重新发起任务；这是一个新任务，不复制候选、步骤、证据或后续补充内容。
- 其他状态仅提供查看/导出等现有操作。
- 复用任务中心现有列表、`CellOperation` 行菜单、`AgentChatTask` 任务卡、Ant Design 按钮/确认交互；不另建视觉模板。

## 用户流程与状态

1. 行菜单按任务状态显示可用动作；详情卡片提供同等动作，避免必须先关闭详情。
2. 继续任务时，用户输入补充内容或从已保存候选中选择；提交任务当前 `revision`，收到新任务快照后更新详情并刷新列表。
3. 取消任务需用户确认；只有 `RUNNING` 可取消。成功后刷新该行和详情状态。
4. 重试失败任务前展示确认，调用现有重试语义并用返回的 task id / 状态更新视图；不创建新的任务字段或绕过后端校验。
5. 请求失败时保留原数据并显示可恢复错误提示，允许重试读取或重新操作。

## 接口与安全

- 继续：`POST /ai/agent/tasks/{task_id}/continue/start`，传 `question` 与任务 `revision`，候选选择字段沿用现有 `AgentApi.Continue`。
- 取消：`POST /ai/agent/tasks/{task_id}/cancel`。
- 重试：调用现有任务启动接口，仅提交旧任务的首条用户问题；提示用户这是新任务并展示新任务编号。
- 所有操作仍限制本人任务；刷新和导出维持当前权限重验。

## 验收

- `WAITING_INPUT` 可从详情和行菜单进入续跑，保留 revision 与候选 ID。
- `RUNNING` 可取消；取消确认前后状态符合服务端响应。
- `FAILED` 可明确重试为新查询；不复制旧任务执行参数或证据。
- `SUCCEEDED`、`CANCELLED` 不显示继续/取消/重试。
- 操作失败有中文反馈，列表刷新后仍显示服务端权威状态。
- 对应前端行为测试通过，并完成类型检查；若浏览器验收环境不可用，交付时注明。

## 接口核对结果

后端任务中心提供按 `task_id` 的继续和取消接口；没有按 `task_id` 重试接口。聊天接口中的 `retry_failed` 不适用于任务中心。任务中心重试因此只复制首次查询文本并调用现有新任务启动接口，不复制旧任务状态、步骤、候选或证据。
