# 任务块二数据库迁移与恢复记录

## 执行顺序

全新数据库使用 `database/schema.sql` 初始化；已有数据库按 `001_inventory.sql` 至 `016_task2_consistency.sql` 的编号顺序执行。任务块二的已有库升级优先使用：

```powershell
.\.venv\Scripts\python.exe scripts\apply_task2_consistency_migration.py
```

脚本会先检查未关闭异常重复组和一到货单多验收记录；发现重复时停止，不会继续添加唯一约束。脚本会按列和索引是否存在执行，成功后可重复运行。

## 迁移前备份

在已有库执行前导出受影响表及依赖的审计数据：

```powershell
mysqldump --single-transaction --routines --triggers chemicalops operation_exceptions quality_acceptances sys_audit_logs > task2-before.sql
```

## 恢复演练步骤

1. 在隔离数据库导入 `task2-before.sql`。
2. 执行 `apply_task2_consistency_migration.py`，确认输出 `task2_consistency_migration_ready=true`。
3. 重复执行同一命令，确认不会重复添加列或索引。
4. 使用并发测试验证异常扫描、重复验收和库存出入库行为。

本次开发库预检发现 45 组历史重复未关闭异常、0 组重复质量验收，因此没有直接修改业务状态或强行添加约束；这批历史数据需要业务确认保留记录后再清理。

如果唯一约束上线后发现需要回滚，先停止写流量并保留现场备份，再执行以下结构回退；业务数据恢复以备份为准：

```sql
ALTER TABLE quality_acceptances DROP INDEX uk_acceptance_delivery;
ALTER TABLE operation_exceptions DROP INDEX uk_exception_active_dedupe;
ALTER TABLE operation_exceptions DROP COLUMN active_dedupe_key;
```

回退后必须重新处理重复数据，不能直接恢复写流量。生产环境的实际恢复以最近一次通过校验的备份为准。
