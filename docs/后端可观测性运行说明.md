# 后端可观测性运行说明

## 组件与数据

- FastAPI `/metrics` 暴露 Prometheus 文本格式指标；现有 HTTP 请求计数和延迟、Redis 缓存/限流、LLM Gateway 请求/耗时/Token 指标继续沿用进程内注册表。
- 任务队列状态从 MySQL `async_task_executions` 汇总，避免只观察 API 进程而看不到独立 Worker 的持久化积压状态。积压按固定队列类型聚合，不包含用户、任务 ID 或业务参数标签。
- `deploy/docker-compose.observability.yml` 提供可选 Prometheus 和 Grafana，不修改现有 Redis、Qdrant、MinIO 服务定义。Grafana 自动加载 ChemicalOps 概览看板。
- 请求日志包含 `request_id` 和 `trace_id`，可用于跨 HTTP 日志关联。当前未创建 OpenTelemetry span，也未把 API 与独立 Worker 串成分布式 Trace。

## 本地启动

先在本机启动 API，使其监听 `127.0.0.1:8888` 并可访问 `/metrics`。然后在 PowerShell 中设置 Grafana 管理员密码并启动监控组件：

```powershell
$env:GRAFANA_ADMIN_PASSWORD = "设置一个本地密码"
docker compose -f deploy/docker-compose.observability.yml up -d
```

Prometheus 默认位于 `http://127.0.0.1:9090`，Grafana 位于 `http://127.0.0.1:3000`。Grafana 用户名默认为 `admin`，密码读取 `GRAFANA_ADMIN_PASSWORD`。需要调整端口时可设置 `PROMETHEUS_PORT` 或 `GRAFANA_PORT`。

Prometheus 每 15 秒抓取 `host.docker.internal:8888/metrics`。如果 API 使用其他端口或地址，请编辑 `deploy/observability/prometheus.yml` 中的目标地址。

## 指标与解释

- API：`chemicalops_api_requests_count` 和 `chemicalops_api_request_duration_seconds_histogram_*`；可用 PromQL `histogram_quantile(0.95, sum by (le) (rate(chemicalops_api_request_duration_seconds_histogram_bucket[5m])))` 计算抓取样本的 P95。
- 队列：`chemicalops_task_queue_backlog`、`chemicalops_task_queue_oldest_ready_seconds`、`chemicalops_task_queue_executions` 和 `chemicalops_task_queue_attempts`。这些是每次 `/metrics` 抓取时对 MySQL 当前状态的快照，不是累计事件计数。
- Redis：`chemicalops_redis_cache_count`、`chemicalops_rate_limit_count`，按固定功能区和结果分类。
- LLM：`chemicalops_llm_gateway_duration_seconds_histogram_*`、`chemicalops_llm_tokens_count` 及 Gateway 错误、重试、熔断和并发等待指标。Token 数只在上游实际返回 usage 时记录；流式模型需支持可选 usage 才能统计。

当前 API/LLM 累计指标是进程内数据。多 API 进程部署时，应为每个进程设置独立 Prometheus 抓取目标，或后续迁移到 Prometheus multiprocess 采集方案；不能把负载均衡地址当成完整的多进程累计数据。队列状态来自共享 MySQL，因此能反映独立 Worker 的持久化任务状态。当前未持久化每次执行的开始时间，故不暴露虚构的任务执行耗时；需要该指标时应先新增带迁移的执行时间字段。

## 可重复接口压测

```powershell
python scripts/run_load_test.py --url http://127.0.0.1:8888/health --requests 200 --concurrency 10
```

脚本输出请求数、并发数、错误数、RPS、P50/P95 和状态码分布。报告结果时同时记录测试机、API 实例数、数据库/Redis 状态、请求路径、样本数、并发数及模型是否参与；`/health` 仅验证服务端点，不代表业务接口或模型性能。
