## 1. 需求理解与规则

用户需要按岗位职责控制三个层级：

1. **一级功能区**：侧边栏的运营总览、主数据、采购管理、仓储管理、质量管理、财务管理、运营中心、AI 工作台、系统管理。
2. **二级页面**：例如仓储管理下的到货与收货、库存台账、库存调拨等。一级功能区可见，不代表其全部子页面可见。
3. **三级操作**：页面里的新建、修改、删除、提交、执行、审批、复核、导出等。页面可见，不代表其全部操作可见。

管理员拥有全部应用功能权限。普通角色只显示职责内的功能和操作。采购专员在本文件中对应现有「采购员 BUYER」，不另建同义角色；财务经办对应「财务专员 FINANCE_CLERK」。

**无权限的操作直接隐藏**，包括工具栏、行菜单、批量菜单、详情页按钮、编辑表单入口和 AI 推荐动作。不能先允许打开编辑窗口，再在保存时告知没有权限。

有权限但当前状态不满足时，默认保留按钮并禁用，说明原因；完全不适用于当前记录的动作可隐藏。管理员的全权限仍受状态机、引用关系、库存可用量和数据完整性约束，不等于任意覆盖已定稿记录或删除审计事实。

本文件采用「目标规则」与「现状证据」分离的方式：用户明确的管理员全权限、无权入口隐藏为确定要求；其他岗位的具体分工为本次建议基线，不宣称已经得到业务确认或已经实现。

## 5. 三级操作权限（目标白名单）

以下每行「允许角色」均**默认包含管理员**，只列其他角色。未列出的角色全部无权限，相关控件隐藏；如果其页面有「阅」权限，仅保留查询、详情和已授权的只读内容。角色同时具有多个身份时可合并功能权限，但不得绕过记录范围、状态约束和同笔业务的职责分离。

「建议拆分」是未来权限设计，不能直接作为已有权限码使用。「现有码」只能说明当前接口粒度，不能证明目标分工已生效。

### 5.6 运营中心与通用操作

| 页面 / 具体操作 | 允许角色（除管理员） | 约束 |
|---|---|---|
| 运营异常：登记、修改、指派、添加任务、记录处理、关闭/重开 | 采经、仓、质、质经 | `operations.exceptions.write`；仅各自负责的业务范围，建议按动作拆分 |
| 列表：搜索、筛选、刷新、分页、查看详情 | 第 4 节具有该页面读取权限的角色 | 仅允许字段和记录；筛选不能扩大范围 |
| 业务数据：导出、批量导出 | 具有对应读取权限且另获准导出的角色 | 建议独立 export 权限；不能默认所有 read 都允许全量导出；未明确授权时控件隐藏 |
| 附件：查看/下载 | 有业务记录读取权限且有相应文件权限的角色 | 对象绑定关系必须校验；不能凭文件 ID 跨记录读取 |
| 附件：上传/替换/关联 | 具有对应业务维护权限且有相应文件权限的角色 | 文件 write/attach 不得单独绕过业务权限 |

导出默认隐藏是建议基线，现有实现未必具有独立 export 权限。后续须确定授权角色与字段范围，再启用；管理员拥有全部已定义导出权限。不存在的控件不因本表描述而自动成为新增功能。

### 5.7 AI 工作台内的子能力与操作

AI 工作台虽然是侧边栏单页，其能力卡片、模式选择、推荐问题、生成结果中的链接和确认按钮同样属于二级/三级权限控制。

| 能力 / 操作 | 目标允许范围 | 显隐规则 |
|---|---|---|
| 业务查询、图表、采购只读查询 | 内部角色且具有所查询业务的读取权限 | 查询来源受同一数据范围控制；无权限业务模式/推荐入口隐藏 |
| 化学品资料问答 | 内部角色且有对应资料读取权限 | 不返回无权读取的文档、附件或供应商资料 |
| 自然语言筛选并打开业务列表 | 有目标页面读取权限的内部角色 | 目标页面隐藏时，不展示跳转/应用按钮 |
| 采购申请草稿整理、确认创建 | 管、采经、采 | 需要采购申请写权限；其他角色的模式与确认创建按钮隐藏 |
| 生成运营晨报 | 获准使用晨报的内部角色 | 只汇总本人可见业务指标，不能统一返回全局财务信息 |
| 生成并推送晨报 | 管 | 建议独立推送权限；普通角色隐藏推送入口和接收人选择 |
| 业务分析中的确认入库、质量结果保存、财务核查写回、异常登记等 | 与对应原业务动作相同的角色 | AI 生成建议不扩大权限，写入仍须业务权限与人工确认 |
| 会话新建、改名、删除本人会话 | 已获准使用工作台的内部角色 | 本人自助动作；不授予他人会话管理权限 |

工作台导航现使用独立 `ai.workspace.read`，仅向内部角色授予；晨报推送权限仍可进一步独立设计。上述为权限分工，不新增 AI 自动审批或自动付款能力。

## 7. 页面内部字段与数据范围

可查看页面后，还必须按字段、记录和关联对象过滤：

| 场景 | 目标控制 |
|---|---|
| 运营总览 | 根据用户决定，全部内置角色可读取相同的全局汇总，包括已付款金额、供应商采购金额、库存成本、异常和有效期指标；该页面权限不代表底层记录读写权限 |
| 供应商详情 | 采、仓、质等只显示职责需要的联系/合作资料；银行账户等敏感字段单独授权 |
| 库存台账、流水 | 数量可读不等于成本可读；非成本授权角色隐藏成本单价、总成本、利润等字段，接口亦不返回 |
| 订单详情中的收货、质量、付款区块 | 各区块分别检查对应读取权限；无权区块/链接隐藏，避免详情页越权 |
| 本人/被分配采购记录 | 列表、详情、编辑、草稿删除、导出使用相同归属规则；read/write 不代表全公司数据范围 |
| 仓库记录 | 按授权仓库限制；调拨同时校验源和目标；不得借库存流水或关联单据突破范围 |
| 供应商门户 | 所有请求绑定当前供应商主体，不接受客户端任意指定 supplier_id；跨供应商详情和确认拒绝 |
| 文件与 AI 引用 | 下载、资料问答、来源引用、推荐链接均校验原记录权限，不能通过独立文件/会话接口绕过 |

用户没有审批权限时，不仅审批按钮隐藏，审批表单、批量审批菜单及快捷入口也要隐藏；不需要因此隐藏其有权查看的审批历史。

## 8. 当前实现与目标差异

## 9. 实现与验收口径

建议判定顺序：账号有效 → 页面读取权限 → 对象在授权范围内 → 动作权限 → 状态/前置条件。前端负责入口体验，后端对每次请求重新校验。隐藏页面的直接 URL、直接 API 和附件地址同样不可绕过授权。

| 验收项 | 可验证结果 |
|---|---|
| 一级目录 | 菜单生成逻辑已改为以有权访问的可见子页面推导分组；12 角色分别登录后的实际目录仍待验证，确认无空父目录 |
| 二级页面 | 无权限子页不出现在侧栏、搜索、页签恢复或快捷入口；直接访问受控 |
| 三级操作 | 工具栏、行菜单、批量菜单、详情、抽屉、AI 推荐中无权操作均不存在 |
| 权限与状态分开 | 无权隐藏；有权但状态不符时禁用并说明；合法记录可办理 |
| 正反例接口 | 合法动作成功；无权、越界、非法状态直接请求被拒绝；分别记录证据 |
| 数据范围 | 同角色不同本人/部门/仓库/供应商记录交叉验证；列表、详情、统计、导出结果一致 |
| 数据字段 | 未授权财务指标、成本、银行账户不在 UI、接口响应、导出或 AI 回答中出现 |
| 职责分离 | 同一人对本人经办记录的审批/复核被拒绝；多角色叠加不能绕过 |
| 权限变更生效 | 撤权、角色调整、账号禁用后，现有会话及已打开页面同步失效；需明确缓存刷新时机 |
| 空数据与异常 | 有办理权限空列表保留；只读仓储空范围隐藏；网络失败不误当撤权 |

每项至少记录：角色、页面、动作、权限码、记录范围、状态、预期显隐、接口结果、执行日期、证据位置。未经验证不得在项目成果文档中写成已完成能力。

## 10. 业务确认项与本次交付边界

5. 同人经办与审批限制的适用业务，以及例外流程。
