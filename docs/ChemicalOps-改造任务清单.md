# ChemicalOps 改造任务清单

> 基线：2026-10-08。下列任务均未在本轮实施，勾选框只在实现及所列验收完成后更新。现有代码和历史测试用于复用及识别差距，不将已有能力重新登记为“从零建设”。
> 配套：[企业级改造方案](ChemicalOps-企业级改造方案.md) · [项目介绍与成果（STAR）](项目介绍与成果（STAR）.md)

## 执行约定与依赖

任务按 P0→P1→P2→P3 放行。只读 AI、真实样本准备和监控设计可在接口契约稳定后并行推进，但通用写工具必须等待对应 P0 领域规则与 P1 执行幂等验收。编号标明主要依赖，开发时继续检查实际代码和已有 OpenSpec 变更，避免重复或覆盖他人工作。

每项交付应包含变更文件、迁移/兼容方案、适合风险的测试、验收日期/环境/样本/结果和限制。测试失败或跳过单列；受影响集合与复跑不能相加。文档更新以本清单和直接相关操作说明为主，README 与 STAR 仅按项目规范的触发条件编辑。提交和推送需用户明确授权。

前端全部复用现有列表、业务弹窗、产品编辑抽屉与来源悬浮窗，通过字段、配置、属性和插槽扩展；保留字体、尺寸、间距和交互。新增能力优先扩展原组件，不另造视觉模板。未浏览器验收时必须说明。

## P0：业务正确性

当前问题：已有模拟采购闭环、状态校验、库存批次及财务匹配，但行级放行、可追溯预留、异常结算和全权限/并发组合仍不完整。放行门禁：下面 P0 任务通过，核心历史回归无退化。

### P0-01 状态、数量及金额契约盘点

- [ ] 完成领域契约与可执行测试矩阵。
- **模块/优先级**：purchase_requests、rfqs、purchase_orders、deliveries、quality_acceptances、inventory、finance；P0。
- **实施步骤**：盘点路由和服务的合法转换/权限/事务；标明订单 COMPLETED=实收履约完成；保留先确认对账再提交核验发票的现有流程；定义合格、隔离、拒收、退货、应付和预留口径，明确单位、舍入和历史兼容；为每个转换列正向、重复、非法状态、越权样本。
- **依赖/风险**：无；未经口径确认就新增状态会导致库存和财务分歧，不直接批量改历史状态。
- **验收**：每个现有写入口均能映射到规则表；收货完成与质量/结算分开显示；历史 0 版对账边界和 0～6 位精度不变；新增未实现规则显式标注。

### P0-02 事务与跨域写入边界

- [ ] 对高风险用例建立单一事务所有者。
- **模块/优先级**：各域 service/crud、core/db.py；P0。
- **实施步骤**：列出跨域 ORM 写入和嵌套 commit；先改收货、放行入库、退货影响应付等用例；领域子方法 flush，编排统一提交；规定锁顺序与异常回滚；业务审计、通知意图/outbox 同事务保存。
- **依赖/风险**：P0-01；现有独立调用不能因移除 commit 丢失持久化，避免长事务等待远端服务。
- **验收**：在任一数据库写入步骤注入异常，单据、数量、金额、审计及投递意图全回滚；事务不等待模型/Broker；锁顺序有并发验证。

### P0-03 部分到货、取消剩余量与拒收

- [ ] 补齐履约异常和数量状态。
- **模块/优先级**：purchase_orders、deliveries、supplier_portal、operation_exceptions；P0。
- **实施步骤**：复用实收/短交行锁，补并发登记和收货组合；为已下单取消剩余量设计受控变更与版本，既有到货不删除；定义供方拒绝、全拒收及短交后补货的引用关系；前端复用收货弹窗与行操作菜单。
- **依赖/风险**：P0-01、P0-02；取消与收货竞争、已计划未收数量的占用口径需明确。
- **验收**：10 单位订单 6+4 分批收货正确；同时提交两笔超剩余量收货只允许合法结果；重复收货不增量；取消剩余量后旧请求拒绝；越供应商写入被拒绝并留痕。

### P0-04 行级质量放行与复检纠正

- [ ] 将分行检测内容扩展为分行放行数量。
- **模块/优先级**：quality_acceptances、deliveries、inventory、files；P0。
- **实施步骤**：新增放行明细与版本迁移；保存实收/合格/隔离/拒收数量、检测来源和人员；入库额度按有效放行扣减；复检追加版本，已入库改判走冻结与纠正；沿用质量结果弹窗/报告复核组件。
- **依赖/风险**：P0-01、P0-02、P0-03；旧整单结果不能猜测行级合格量，人工核对后回填。
- **验收**：首批 6 中合格 5、隔离 1，仅 5 可入库；两次入库累计不超合格量；并发放行/入库不超额；复检变差不静默改已用库存；来源、前后版本和操作者可查。

### P0-05 库存预留、冻结与释放

- [ ] 建立预留来源及锁定量投影一致性。
- **模块/优先级**：inventory、inventory_returns、inventory_cost、replenishments；P0。
- **实施步骤**：复用余额/批次/流水；新增 ACTIVE/CONSUMED/RELEASED/EXPIRED 预留明细；按来源关联申请，批准/取消/执行/到期维护 locked_quantity；冻结批次禁止新出库；对账工具检查明细总量与投影差异，不自动抹平。
- **依赖/风险**：P0-02、P0-04；历史锁定量来源缺失，需隔离差异与人工修复；锁定量不与质量隔离量重复扣减。
- **验收**：两个并发申请不超同批次可用量；取消、超时、重复释放只影响一次；出库同时更新余额、预留及流水；冻结库存不计可用；不同单位不合计，数量守恒有断言。

### P0-06 部分放行、退货与财务纠正闭环

- [ ] 扩展行级应付并保护历史票行依据。
- **模块/优先级**：finance/service.py、reconciliation_items.py、invoice_matches.py、inventory_returns；P0。
- **实施步骤**：复用来源 hash、匹配版本、Decimal 和双人核验；应付依据接入有效放行/退货行；增加部分结算规则而非直接放宽整单 ACCEPTED 检查；规划并实现首版已核验票反向冲销；付款行分配与一票跨对账单单独评审，首版可保持禁止。
- **依赖/风险**：P0-01、P0-02、P0-04、P0-05；税务验真/真实支付接入需另立任务，不把模拟冲销当成税务合规结论。
- **验收**：9 合格入库后退 2，应付、成本和来源快照一致；来源变化使旧提交拒绝或处理记录重开；驳回释放额度；同人核验拒绝；核验后不直接作废旧票；原六组/八票及精度测试保持通过。

### P0-07 关键业务幂等与版本冲突

- [ ] 补齐 HTTP 幂等之外的副作用唯一性。
- **模块/优先级**：core/idempotency.py、system/idempotency_model.py、采购/库存/财务；P0。
- **实施步骤**：保留既有响应重放；给入库、收货、预留、放行、匹配等关键命令设业务唯一键；持久化参数 hash 和结果引用；补交互更新 version 条件；列出流式/登录豁免及未覆盖动作。
- **依赖/风险**：P0-02～P0-06；不得把中间件缓存与领域提交混同一个原子事务。
- **验收**：同键同参重放相同结果、同键异参冲突；数据库提交后响应丢失仍只产生一份流水；并发新建唯一性由 MySQL 证明；旧版本编辑 409；无重复额度占用。

### P0-08 全入口授权与角色回归

- [ ] 统一 API、附件、聚合及历史来源权限。
- **模块/优先级**：core/auth、purchase_orders/scope、supplier_portal、files、finance、ai 与前端；P0。
- **实施步骤**：维护功能权限+资源范围矩阵；复用本人/部门/供应商绑定条件；覆盖列表、详情、下载、导出、状态变更、AI 证据；修复/隔离历史 finance_clerk 401 的测试认证前置问题，重跑受影响集合；补全角色按钮抽查。
- **依赖/风险**：P0-01；权限扩大不能用来修复测试登录，管理员样本不能代替普通岗位。
- **验收**：跨供应商/部门/本人越权均拒绝，已授权入口正常；记录测试账号前置状态；历史 37 项复跑失败有明确解决证据；按 11 类非管理员角色补三级页面和详情操作矩阵，不沿用 1,740 次拒绝作为新结果。

## P1：任务可靠性

当前问题：队列机制已有 2026-10-08 专项验收，默认仍为 in_process；长期 Worker、完整 Linux 环境、外部副作用和交付标准仍需验收。门禁：真实依赖故障矩阵与灰度回滚通过，P0 领域幂等可复用。

### P1-01 队列长期运行与故障矩阵

- [ ] 将现有可选能力纳入隔离 Compose 集成验收。
- **模块/优先级**：task_queue、jobs/technical_documents、ai/agent_runtime、三个任务 CLI；P1。
- **实施步骤**：复用迁移 041、dispatcher/worker/监督机制；在隔离 MySQL/Broker/Qdrant 验证持久化、重复、丢 ACK、投递 confirm 后落库前崩溃；扩大至完整 Linux Worker；补失败队列查询、处置和重投权限。
- **依赖/风险**：P0-02、P0-07、P0-08；模型/embedding 替身与真实调用分层，不在已有知识集合写验收点。
- **验收**：Broker 停机能接收持久任务、恢复自动补发；Worker 崩溃旧 token 不提交；取消/超时/撤权终止执行；无法证明旧进程停止则隔离并保留锁；重投无重复业务副作用；新结果不简单复用历史 222 项。

### P1-02 重试预算、Checkpoint 与副作用账本

- [ ] 明确任务/节点重试和不确定执行结果。
- **模块/优先级**：task_queue/adapters、execution、ai、doc_kb、外部适配；P1。
- **实施步骤**：分类瞬时/永久/不确定错误；保留 3 次与 30/120 秒基础并配置总预算；定义 checkpoint Schema/版本和可恢复步骤；外部写入保存 operation ID、请求 hash、幂等键和结果，未知结果查询或人工核对。
- **依赖/风险**：P1-01、P0-07；MySQL/Qdrant 非原子，模型费用无法保证零重复，自动重试不得掩盖 unknown。
- **验收**：投递失败不消耗执行次数；任务和节点重试不相乘突破预算；恢复不重复已提交写入；旧 checkpoint 可迁移或明确拒绝；向量旧代次不能覆盖/复活正文。

### P1-03 全栈容器与启用/回滚标准化

- [ ] 交付可从空环境启动的完整 Compose。
- **模块/优先级**：deploy、API/前端、Worker/Dispatcher、配置；P1。
- **实施步骤**：扩展已有 RabbitMQ/MinIO Compose，加入 API、前端、MySQL、Qdrant 与 Worker，必要调度器独立；固定镜像、持久卷、健康检查、资源上限、网络和 secrets；先 documents 后 agent，回滚先结束/隔离旧任务。
- **依赖/风险**：P1-01、P1-02；管理端口暴露、默认密码、队列任务双路径执行需禁止。
- **验收**：干净隔离环境可启动并完成模拟链路；重建保留数据；错误生产配置拒绝启动；分阶段开关与回滚后新任务只走一个路径；就绪/存活策略与依赖故障行为有记录。

### P1-04 迁移管理决策与备份格式验证

- [ ] 建立 SQL 台账延续或 Alembic 接管的唯一管理方式。
- **模块/优先级**：database/migrations、migrate_database、backup_mysql、backup_development_database、restore_mysql、CI；P1。
- **实施步骤**：盘点全部迁移/schema/台账；在空库、上一版本库和 DDL 中断库验证升级；评审 Alembic 接管收益，采用时建立 baseline 与停用旧写入入口；区分 .sql 和 JSONL.gz 备份，补各格式恢复支持或明确限制；记录对象/索引备份清单。
- **依赖/风险**：P0 新模型迁移、P1-03；不得在原开发库测试覆盖恢复；MySQL DDL 不保证事务回滚。
- **验收**：重复升级无额外副作用；中断可继续且校验和冲突明确；两种备份格式有独立验证或明确“不支持恢复”；隔离恢复核对 schema、行数、金额和来源，不仅核对文件生成。

## P2：AI 产品化

当前问题：四工具只读编排及专用采购草稿已有，通用写确认、统一预算、知识发布和真实业务评测仍不完整。门禁：安全边界零放行，质量指标分层评估。

### P2-01 Tool Gateway 与可控上下文

- [ ] 在既有 ToolSpec 和 RunState 上扩展网关与预算。
- **模块/优先级**：ai/agent_tools、agent_runtime、agent_prompt、model/schema；P2。
- **实施步骤**：统一 Schema/版本/权限/风险/超时/日志；结构化记忆只保存目标、候选及引用；按任务/模型/工具设置限额，摘要历史并重新读取新鲜数据；工具返回结果截断可解释，usage 缺失标 unknown。
- **依赖/风险**：P0-08、P1-02；不能增加工具后直接复用原四工具评估分母。
- **验收**：非白名单、额外参数、越权与注入指令拒绝；上下文膨胀不会突破预算；来源/数值隔离回归不退化；日志有任务/工具/trace ID，无密钥和敏感全文。

### P2-02 通用 HITL 首个写用例

- [ ] 首版只开放受控采购申请草稿创建。
- **模块/优先级**：ai/drafts、agent_runtime、purchase_requests、工作台；P2。
- **实施步骤**：复用专用预览；新增确认快照/有效期/一次性标识；前端沿用业务弹窗展示动作、对象、数量、依据；执行前重验参数 hash、用户/归属、业务版本及状态，再调用 P0 服务；记录执行结果。
- **依赖/风险**：P0-01、P0-02、P0-07、P0-08、P1-02、P2-01；订单审批、库存执行和资金操作保持正式授权入口，后续逐项评审。
- **验收**：未确认不写入；同确认并发重放仅一份草稿；撤权、过期、版本变化拒绝并要求新预览；Worker 崩溃恢复不重复创建；取消与确认竞争有确定结果。

### P2-03 编排恢复边界与快照升级

- [ ] 验证节点边界恢复，按需接入持久 Checkpointer。
- **模块/优先级**：ai/agent_runtime、task_queue、任务模型；P2。
- **实施步骤**：盘点现有 plan/execute 和 checkpoint；固定消息/对象/工具结果恢复规则；在模型响应、工具返回、结果提交各边界注入崩溃；评估是否需要 LangGraph 持久 Checkpointer，接入时统一 task/thread/revision 与代次；WAITING_INPUT 释放执行资源。
- **依赖/风险**：P1-02、P2-01、P2-02；不能宣传任意节点恢复，副作用提交边界要先明确。
- **验收**：每个支持恢复边界有独立故障测试；不重复已提交写入；旧 revision 无权覆盖新确认/取消；快照不兼容明确失败或迁移。

### P2-04 文档生命周期、权限与解析门禁

- [ ] 新建知识复核发布和主体隔离流程。
- **模块/优先级**：files、doc_kb、jobs/technical_documents、parse_tds_msds、前端；P2。
- **实施步骤**：盘点通用附件与技术资料入口；新增原件/发布版本、ACL、审核人与状态；统一 MinerU 适用格式优先及 VL 条件补识/本地回退；发布前复核，索引分阶段切换；召回前后及上下文前校验权限/有效版本。
- **依赖/风险**：P0-08、P1-02、P1-04；索引异步滞后不能泄漏停用/越权资料，保留原章节引用。
- **验收**：未发布、停用、撤权文档不进入回答，即使旧向量仍存在；解析失败不发布；修订不破坏旧审计；源变更重新解析、源未变复用；真实解析样本与替身故障测试分别报告。

### P2-05 属性标准化、检索与引用验证

- [ ] 为高频化学品问题建立结构化证据。
- **模块/优先级**：chemicals/products、doc_kb、embedding/retrieve/vector_store、AI 来源组件；P2。
- **实施步骤**：复用 CAS/别名解析，新增型号与属性原值/标准单位/条件/章节；结构化过滤结合召回；用固定评测比较重排前后；引用显示文档版本、章节与页码（可得时）；冲突/无来源拒答。
- **依赖/风险**：P2-04；模型抽取不能替代化学品质量判定，单位换算需适用条件。
- **验收**：同物质不同型号不误合并；条件不一致不直接比较；每个关键属性可追溯；名称 149/149 与召回结果独立报告；重排收益以新增检索评测证明。

### P2-06 真实样本与分层评测
