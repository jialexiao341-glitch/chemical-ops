# 采购 Agent MVP：业务规则与验收用例

> 版本：v1.4｜日期：2026-10-03｜适用范围：开发环境的单产品采购辅助。
> 本文冻结首期开发规则，尚不是生产采购政策。当前已实现四个只读工具、模型决策循环、多候选追问、任务保存与补充续跑；只读任务已集成到原工作台聊天，支持会话历史恢复和原输入框补充。确定性来源/数值回归 30/30 通过；聊天集成后真实模型首跑 15/16 严格 outcome 通过，T14 单例复核通过但状态有波动。完整角色/状态浏览器矩阵、阶段门、确认写入和故障恢复仍待验收。回归结果见第 6 节及[阶段矩阵](evaluation/Agent阶段0-3验收矩阵.md)。

## 1. 首场景与完成定义

目标：用户明确产品后查询授权仓库内的账面可用库存，在指定询价明细内比较供应商报价，后续整理采购申请预览。后续草稿阶段由用户提供采购数量、单位、用途；只读查询无需这些字段，Agent 不推算用户的采购数量，也不把“需求数量减库存”直接当作应采购数量。是否使用库存、是否采购及供应商选择仍由用户决定。

后端只读任务交付：四个工具的目录和输入/输出 Schema 可读取；认证任务 API 支持模型根据结果选择下一步、追问、补充续跑、取消和轨迹回看。多候选不能由模型任意选择；数值摘要由工具证据生成。控制流回归通过，真实模型样本与工作台交付范围见 [运行与验收](Agent只读任务运行与验收.md)。

只读 Agent MVP 完成：用户目标能驱动库存与报价工具，工具结果影响下一步；缺字段或产品歧义时追问；完成后汇总来源；安全终止有效且轨迹可回看。

完整采购辅助 MVP 完成：只读 Agent 加采购预览、明确确认、二次鉴权、版本校验、幂等创建 `DRAFT` 与恢复；用户在原流程提交审批。后续阶段门统一见 [企业级改造方案](ChemicalOps-企业级改造方案.md) 和 [改造任务清单](ChemicalOps-改造任务清单.md)。

## 2. 本版冻结的业务口径

| 项目 | 首期规则 | 后续扩展条件 |
| --- | --- | --- |
| 产品 | 关键词检索启用产品与单位，返回型号/包装规格；单个完整命中可定位，多候选需用户选择，续跑重新核验 | 支持别名/化学品关联时保留规格，不自动合并 |
| 库存范围 | 必须有 `warehouse.inventory.read`；沿用 `accessible_warehouse_ids`：管理员/采购经理不限负责人，其余仅自己负责或未指定负责人的启用仓库 | 按业务组织调整时统一改领域服务与 Agent，不单独放宽 Agent |
| 库存口径 | 启用仓库、指定产品；`AVAILABLE` 余额的 `quantity - locked_quantity` 为账面可用，其他余额可用量为 0；分单位合计 | 效期、批次状态、停用单位等资格核查另走业务规则；本版不据账面可用量声称可直接领用 |
| 库存截断 | 最多返回 100 条明细；合计基于全部授权范围的余额，不把前几行合计当总量 | 下钻/分页按相同范围继续查询 |
| 询价范围 | 必须有 `procurement.rfqs.read`；管理员/采购经理全部询价，其余仅 `requester_id == 当前用户` | 对齐现有询价服务的范围规则，不随主数据供应商权限扩大 |
| 报价对象 | 指定 `product_id + rfq_item_id`，必须属于可见的同一询价明细；只接受 `SENT/RESPONDING` 询价 | 产品全局历史报价可作为另一个工具，须保留规格、技术要求、日期和用途差异 |
| 报价版本 | 每个供应商在同一询价的最新版本，版本相同按更大 ID；先选最新，再检查状态和有效期 | 最新版撤回/过期时不能恢复旧版为当前候选 |
| 报价有效性 | 已提交、非未来日期、未过期；供应商和报价单位启用；无有效期报价仅展示，不排序 | 业务明确无有效期报价的政策后再修改规则 |
| 价格比较 | 未税单价；同询价明细、同币种、同单位、同明确税率、同明确供应商型号才排序；相同价格并列排名 | 汇率、单位换算、税差、运费、账期和规格等规则确认后才可计算综合成本 |
| 数量与起订量 | 展示报价数量、MOQ/单位及交期原值，不推断目标数量可成交 | 后续提供需求数量并建立报价区间、MOQ 和换算校验 |
| 不完整结果 | 无记录表示“当前授权范围无符合条件记录”；报价截断时全部不排序 | 禁止推断企业无库存/无供应商，或把截断结果称为全局最优 |
| 写入 | 当前注册表只含 `READ_ONLY` 工具；创建草稿、审批、定标等工具名均拒绝 | 通过确认、幂等和恢复验收后单独开放草稿创建 |

上述报价排序是 Agent 只读展示规则；不会调用现有会落库的 `build_comparison`，不会保存比价快照或变更定标。原询价页面的业务流程仍有独立的规则和人工处理入口。

## 3. 工具协议与接口

实现文件：`backend/app/modules/ai/agent_tools.py`。四个工具提供静态白名单、Pydantic 输入/输出 Schema、权限码、版本和 `READ_ONLY` 标记。调用时重新读取权限并校验参数；输入拒绝 `user_id`、角色、SQL 等未登记字段。库存/报价结果带 UTC 观察时间；报价有效期按中国标准时间 UTC+08 判断。

| 接口 | 用途 | 认证与限制 |
| --- | --- | --- |
| `GET /api/v1/ai/agent/tools` | 返回当前用户有权使用的工具及 Schema | JWT；工具按当前权限过滤 |
| `POST /api/v1/ai/agent/tools/execute` | 执行一个指定只读工具 | JWT + 对应权限 + 资源范围 + 参数校验；关闭 `AGENT_ENABLED` 后拒绝 |

库存调用示例（ID 须替换为本环境有权访问的实际对象）：

```json
{"tool":"inventory.query_available","arguments":{"product_id":1,"warehouse_id":1,"limit":20}}
```

报价调用示例：

```json
{"tool":"supplier_quotes.compare","arguments":{"product_id":1,"rfq_item_id":11,"limit":20}}
```

新增 `catalog.search_products` 与 `supplier_quotes.find_rfq_items` 定位工具；任务入口与动作协议见 [运行与验收](Agent只读任务运行与验收.md)。

库存/报价返回 `sources` 中的 `record_id` 是余额或报价明细 ID；报价明细的 `parent_id` 是询价 ID。前端接入时按业务页面和当前权限转为入口，工作台已按余额产品/仓库打开库存过滤列表，按 parent_id 打开询价来源；来源仍须通过原业务 API 鉴权。该基础接口是显式工具调用，不调用模型；不依赖模型 API Key。写开关不会让目录自动出现写工具。

## 4. 固定样本与核验方法

可执行样本位于 `tests/test_agent_read_tools.py::tool_db`，每次在隔离 SQLite 库生成并销毁，不改本地开发业务库。日期相对中国标准时间当日计算，保持过期/未来等边界含义稳定。

- 用户 7：产品、库存和询价读取权限；用户 8：仅库存读取；用户 9：管理员；用户 10：采购经理并具有产品、库存和询价读取权限；用户 20：无读取权限。
- 产品 1：启用的测试乙醇；产品 2：停用产品。单位 1：千克；单位 2：升；单位 3：停用。
- 仓库 1：用户 7 管理；仓库 2：用户 8 管理；仓库 3：无负责人；仓库 4：停用。
- 余额 1：仓库 1，100 千克、锁定 20，账面可用 80；余额 2：仓库 1，冻结 50 千克，可用 0；余额 3：其他仓库 999 千克；余额 4：公共仓库 5 升；余额 5：停用仓库 888 千克。
- 询价 1/明细 11：用户 7 发起、报价中；询价 2/明细 21：用户 8 发起；询价 3/明细 31：已关闭。
- 明细 11 的 14 条报价覆盖旧版、新版、过期、未来日期、撤回、无有效期、异币种/单位/型号、未知税率、停用供应商/单位；符合展示条件 7 条，完整可比组仅报价 2（10 CNY/千克）和报价 3（8 CNY/千克）。

字段和数量按独立预期值核验；SQL 执行事件检查只出现 SELECT。测试对身份/权限使用替身，查询本身执行真实 SQL。HTTP 回归另检查未登录和请求字段校验。样本结果不能替代真实采购资料、完整角色矩阵或模型任务级评估。
