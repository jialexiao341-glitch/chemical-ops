# 测试覆盖与发布门禁

本文记录第六项“测试覆盖与发布门禁”的当前实现和边界。自动化结果只证明 CI 实际运行过的场景；对象存储、扫描器和备份恢复仍需按部署环境单独验收。

## 自动门禁

GitHub Actions 工作流位于 `.github/workflows/ci.yml`，在 push 和 pull request 上运行：

| 门禁 | 执行内容 | 目标风险 |
|---|---|---|
| 后端语法检查 | 编译 `backend/app`、`scripts` 和 `tests` | 尽早发现语法错误 |
| 全新 MySQL 初始化 | MySQL 8 空库运行受保护的初始化脚本，按序应用全部迁移，再创建测试账号和主数据 | 验证空库建表、迁移顺序和测试环境准备 |
| 迁移升级与恢复 | 检查最新版本；重复升级保持无变化；从 020 升到当前版本；模拟 022 的 DDL 已执行但台账未写入，再重试升级 | 验证旧版本升级、重复执行和 MySQL 隐式提交后的恢复路径 |
| 后端测试 | 在真实 MySQL 8 上运行 pytest，启用严格配置和 marker 校验 | 覆盖接口、权限、业务状态机、事务、幂等和并发相关行为 |
| 后端安全扫描 | `pip-audit` 与 Bandit | 发现依赖漏洞及常见 Python 安全问题 |
| 前端门禁 | ChemicalOps 类型检查和生产构建 | 验证前端契约与发布产物 |
| 前端依赖扫描 | `pnpm audit --audit-level high`，高危告警会使任务失败 | 防止已知高危依赖漏洞通过发布门禁 |

CI 设置 `CI=true`。若 MySQL 连接失败，`tests/conftest.py` 会让测试失败，不允许将整套集成测试标为跳过后仍显示绿色。

## 现有场景覆盖

- 采购申请、询价比价、采购订单、到货、质量验收和运营异常状态机：`tests/test_procurement_state_machines.py`。
- 关键写入失败后的事务回滚：`tests/test_failure_injection.py`。
- 库存并发出库、幂等请求、财务、供应商门户、附件权限和文件处理：对应 `tests/test_*_api.py`、`tests/test_concurrency.py` 与文件测试模块。
- 生产配置 fail-closed 规则：`tests/test_production_config.py`。
- Prometheus 延迟直方图格式和调度重试次数记录：`tests/test_observability.py`、`tests/test_scheduler.py`。

## 本地复现

先准备隔离的测试 MySQL 和 `.env`，不要将开发库或生产库用于会写入数据的集成测试。初始化空测试库后运行：

```powershell
uv run python scripts/init_database.py
uv run python scripts/seed_demo_master_data.py
uv run python scripts/seed_demo_accounts.py
uv run python scripts/migrate_database.py status
uv run python -m pytest --strict-config --strict-markers -q -rs
```

初始化脚本会拒绝已有表的数据库。已有测试库只需按实际台账执行迁移，不能再次运行含有全量建表 SQL 的空库初始化路径。

## 尚需部署环境验收的内容

- CI 暂不启动 MinIO、ClamAV、Qdrant 或真实 AI provider；相关故障替身与服务级集成矩阵仍需补充。
- CI 不代替预发布环境的不同角色闭环、readiness 告警演练或生产配置核验。
- 数据库备份恢复需要在隔离目标库执行定期演练，并记录恢复耗时、RPO/RTO 和核心业务校验结果；普通 CI 不使用或恢复任何用户备份。
- 并发测试使用真实 MySQL，但测试覆盖的竞争路径仍应随着新增关键写接口扩展，并记录连接数、worker 数及通过条件。
