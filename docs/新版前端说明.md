# ChemicalOps 新版前端说明

> 本文说明新版前端做了什么、验证到什么程度、还有哪些没做。
> 记录时间：2026-09-21。

## 一、概况

旧前端（React + react-antd-admin）已删除，新版基于 **Vben Admin 5.8** 重建。

| 项 | 说明 |
| --- | --- |
| 位置 | `frontend-design/apps/web-chemicalops`（workspace 应用） |
| 技术栈 | Vue 3.5 / TypeScript / Vite 8 / antdv-next / vxe-table / Pinia / Tailwind 4 |
| 工程形态 | pnpm workspace monorepo，`packages/` 与 `internal/` 为 Vben 原样复用 |
| 代码量 | 126 个源码文件（52 个页面组件、24 个 API 模块、7 个路由模块） |
| 后端 | FastAPI，`http://127.0.0.1:8888`，前端 dev 代理 `/api` 与 `/health` |

选择"在 Vben monorepo 内新建 app"而不是自己搭框架，是为了直接复用 Vben 的
表格 / 表单 / 布局 / 权限 / 主题体系，避免重造轮子。

## 二、做了什么

### 1. 与后端的接口契约适配（最关键的部分）

后端**不符合** Vben 的默认约定，请求层按真实协议重写：

| 项 | Vben 默认假设 | ChemicalOps 后端实际 | 处理方式 |
| --- | --- | --- | --- |
| 成功响应 | `{code:0, data:{...}}` | 直接返回业务体 | `successCode: () => true` + `dataField: (body) => body` |
| 错误响应 | `{code, message, error}` | `{code, message, detail}`，HTTP 非 2xx | 优先透传后端中文 `message`，422 时拼接 `detail` |
| 登录返回 | `{accessToken}` | `{access_token, token_type, expires_in}` | 字段适配 |
| 令牌刷新 | 有 `/auth/refresh` | **没有** | 关闭自动续期，401 直接重新登录 |
| 退出登录 | 有 `/auth/logout` | **没有** | 前端清 token（JWT 无状态） |
| 权限码 | 有 `/auth/codes` | 来自 `/auth/me.permission_codes` | 登录时一并拉取 |
| 菜单 | 有 `/menu/all` | **没有** | 前端静态路由 + `meta.authority` 匹配权限码 |
| 分页 | `page` / `pageSize` | `page` / `page_size`，响应 `{items,total,page,page_size}` | 表格代理层转换 |

另外 `RequestClient` 没有 `patch` 方法，所有 PATCH 统一走
`requestClient.request(url, { method: 'PATCH', data })`。

### 2. 权限体系

后端没有菜单接口，因此采用**前端路由 + 权限码**方案：

- 每个路由声明 `meta.authority: ['procurement.orders.read']` 这类后端权限码
- 路由守卫把用户的**角色码与权限码合并**后参与匹配（`router/guard.ts`）
- 按钮级权限用 `v-access:code` 或表格操作项的 `auth` 字段

实测有效：`procurement_manager` 访问 `/system/*` 会 404（路由被过滤），
`system_admin` 可正常访问。

### 3. 已实现的页面

| 模块 | 页面 |
| --- | --- |
| 登录 | 账号密码登录、登录态恢复、401 重新登录弹窗 |
| 全局 | 深色侧栏布局、面包屑、多标签页、通知铃铛（接真实接口）、站内通知中心 |
| 运营总览 | 8 项 KPI、采购金额趋势、订单状态环形图、供应商采购额、待办、有效期预警 |
| 主数据 | 化学品、产品规格、供应商（增删改查 + 筛选 + 分页） |
| 采购管理 | 采购申请（含明细行编辑、提交/审批/驳回/取消）、询价与报价（发送、录报价、生成比价、确认中选、生成订单）、采购订单（提交/审批/下单/取消 + 详情页含进度条与事件时间线） |

### 4. 工程化

- 枚举字典集中在 `src/constants/dictionary.ts`，取值逐个对照后端 schema 核对
- DECIMAL 尾零处理、日期格式化统一在 `src/utils/format.ts`
- 主数据名称缓存 `src/utils/lookup.ts`，把 `product_id` 这类外键渲染成名称
- 通用明细行编辑器 `src/components/items-editor/`，采购申请、询价单、到货计划复用

## 五、发现的问题（需要后端/数据侧跟进）

### 1. 演示数据里存在非法状态 `PLACED`

`scripts/load_development_dataset.py:291` 写入订单状态 `"PLACED"`，
但后端业务代码统一使用 `ORDERED`（`place_order` 进入 `ORDERED`），
`database/schema.sql` 的状态注释也只有
`DRAFT、APPROVING、APPROVED、ORDERED、PARTIAL、COMPLETED、CANCELLED`。

影响：当前库里有 3 条订单处于 `PLACED`，**无法走正常流程**
（例如登记到货要求订单为 `ORDERED` 或 `PARTIAL`）。

前端处理：字典未收录该值，界面按"显示原始码"降级，让异常可见而不是被错误翻译。

建议：统一为 `ORDERED`，并修正种子脚本。

### 2. 演示数据集中在同一天

Dashboard 的采购趋势只有 `2026-09-17` 一天有数据（125 单），其余 29 天全为 0，
所以趋势图看起来"只有一根柱子"。这是数据特征不是前端缺陷，但演示效果不好，
建议种子脚本把订单日期铺开到多个月份。

### 3. 列表接口不返回关联角色

`GET /system/users/{id}` 不返回 `role_ids`，导致编辑用户时无法回显已有角色。
前端目前的做法是"角色留空 = 保持不变"并在界面上提示，
但用户体验不理想。建议后端在 `UserRead` 中补充 `role_ids`。

## 六、启动方式

```powershell
# 后端
cd C:\self_project\ChemicalOps
uv run main.py run --env=dev          # http://127.0.0.1:8888

# 前端
cd C:\self_project\ChemicalOps\frontend-design
corepack pnpm install
corepack pnpm dev:chemicalops         # http://localhost:3000
```

换机器重装依赖时先 `corepack prepare pnpm@11.16.0 --activate`，
并注意 `@iconify/json` 的下载问题（详见 `docs/build-notes/前端构建环境说明.md`）。
