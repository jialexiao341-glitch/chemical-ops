# 数据库设计说明

> 本文按 `database/schema.sql` 的表定义及 `database/migrations/*.sql` 逐项整理。字段、注释、索引与外键只记录 DDL 中可核实的内容；应用层可能另有无外键的逻辑关联。执行初始化前请注意：`schema.sql` 含 DROP TABLE 语句，只能用于空库初始化流程。

`schema.sql` 是初始化快照，后续迁移还会新增表并修改快照中的列与索引。以下表清单和逐字段说明以该快照为基础；迁移 `015`—`028` 新增或变更的结构须同时查看对应 SQL。具体环境结构以已应用迁移版本为准。

## 阅读说明

- `可空` 按列定义是否包含 `NOT NULL` 判断。
- `默认值` 按 DDL 的 `DEFAULT` 子句记录；未声明时显示“—”。
- 索引顺序按 DDL 原样列出，复合索引字段顺序有意义。
- 外键只列 DDL 明确声明的约束；应用层通过服务逻辑维护的关联会在关系说明中标成“逻辑关联”。
- 字段“描述”仅采用 DDL `COMMENT`；无注释标为“未在 DDL 注释”。

## 表结构明细

### `sys_departments` — 组织部门

| 字段 | 类型 | 可空 | 默认值 | 描述 |
|---|---|---:|---|---|
| `id` | `BIGINT UNSIGNED` | 否 | — | 主键 |
| `parent_id` | `BIGINT UNSIGNED` | 是 | — | 上级部门 ID，根部门为空 |
| `department_code` | `VARCHAR(64)` | 否 | — | 部门编码 |
| `department_name` | `VARCHAR(128)` | 否 | — | 部门名称 |
| `manager_id` | `BIGINT UNSIGNED` | 是 | — | 部门负责人用户 ID |
| `status` | `VARCHAR(20)` | 否 | 'ACTIVE' | ACTIVE 启用，INACTIVE 停用 |

- `PRIMARY KEY (id)`

**外键关系**：`fk_department_parent`：(parent_id) → `sys_departments`(id)

## 跨表关系与常用查询路径

以下是代码/DDL能够支持的关系路径。具体连接条件应优先采用同名 `*_id` 与 DDL 外键；没有外键时为逻辑关联，不代表数据库强制完整性。

| 场景 | 关联路径 | 用途与注意事项 |
|---|---|---|
| 用户授权 | `sys_users` → `sys_user_roles` → `sys_roles` → `sys_role_permissions` → `sys_permissions` | `user_id`、`role_id`、`permission_id` 连接；多角色结果需去重。
| 采购申请与审批 | `purchase_requests` → `purchase_request_items`；审批记录关联申请及用户 | 申请主表承载状态/申请人，明细承载产品、数量等；审批轨迹按时间排序。
| 询价与供应商报价 | `rfqs` → `rfq_items` / `rfq_suppliers` → `supplier_quotes` → `supplier_quote_items`；比较单 → 比较明细 | 同一询价可有多个供应商报价；汇总报价时应明确币种、状态与询价明细粒度。
| 采购订单到货与质检 | `purchase_orders` → `purchase_order_items`；`deliveries` → `delivery_items` → `quality_acceptances` | 到货与质量记录需按各自明细/业务标识过滤，避免多对多明细直接连接导致金额或数量重复累计。
| 合格入库与库存 | `quality_acceptances` → `inventory_batches` → `inventory_balances`；批次再关联产品、仓库/库位 | 质量验收结果决定业务流转；余额、交易流水、成本层是不同事实表，不应互相替代。
| 库存操作 | 领料/调拨/盘点/退货/补货主表 → 对应 items；执行结果写入 `inventory_transactions` 等 | 主单用于审批/状态，流水用于库存变动审计。
| 财务结算 | `finance_reconciliations`、`finance_invoices`、`finance_payments`、`finance_settlements` 与采购订单/供应商 | 财务状态是人工录入/确认链路；不能据此推断已对接银行或税务平台。
| 文件附件 | `sys_files` → `sys_file_attachments` | 资源类型与资源 ID 将文件元数据挂接业务对象；对象存储中的文件内容不在业务表内。
| 运营异常与任务 | `operation_exceptions` → `operation_tasks` → `operation_task_comments` | 异常、责任任务和跟进评论分层保存。
| AI 会话运行 | `ai_conversations` → `ai_messages`；`ai_runs` → `ai_run_steps` / `ai_tool_calls` / `ai_action_approvals` | 会话内容、运行步骤与工具/审批记录用途不同。

## 联合索引与查询建议

- 联合索引左前缀有效：查询条件通常应覆盖索引首列开始的一段字段；不要假定交换列顺序仍可命中。
- 等值筛选列通常放在范围筛选列之前，但应结合真实查询计划、数据分布和排序要求核实；本文不推断 DDL 未定义的索引。
- 外键不总是索引的替代品。检查表明某些关联依赖已有索引或业务约束；新增索引前先用 `EXPLAIN` 和实际慢查询验证。
- 多条一对多明细同时 JOIN 时，主表字段会被放大。应先按明细维度聚合，或拆分查询后合并。
- 时间字段建议使用半开区间（`>= start AND < end`），以便边界清晰。

| `revision` | INT，默认 0 | 版本条件更新，防重复续跑和旧运行覆盖取消 |
| `payload` | JSON | 用户问题、公开工具步骤/参数/结果/来源及已选择对象；不含模型思维链 |
| `reply` | TEXT | 证据摘要、追问或停止说明 |
| `error_code` | VARCHAR(64)，可空 | 规范化错误类别 |
| `created_at` / `updated_at` | DATETIME(3) | 应用写入 UTC 时间 |

每步结果保存快照；等待输入后可续跑，但重新查询本轮事实与当前权限。没有后台恢复器、租约或运行中断自动重放，不将该表描述为完整持久化 Checkpointer。保留期限尚需按部署场景制定；详见 [任务运行文档](Agent只读任务运行与验收.md)。
