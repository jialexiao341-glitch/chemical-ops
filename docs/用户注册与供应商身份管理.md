# 用户注册与供应商身份管理

## 注册与审批

登录页的“创建账号”进入 `/auth/register`。申请人可选择头像，填写账号名、姓名、密码，并选择一个启用的非管理员角色；邮箱和手机号选填。提交后账号为“待审核”，不会签发登录令牌。

账号名用于唯一登录标识，姓名用于界面显示，二者分别保留。新注册的账号名与密码均须为 8–16 位，同时包含大写和小写英文字母；账号名仅支持字母、数字和下划线。输入框不预先显示规则，提交不符合要求时通过弹窗提醒，后端独立执行相同校验。已有账号继续使用原账号名和密码登录。

注册头像与个人中心复用同一个头像选择组件，支持 JPG/PNG/GIF/WebP，原图不超过 10MB，自动压缩到最长边 256px 后随注册提交；注册前只在浏览器本地预览。后端复用个人资料头像解码与格式/大小校验，审批通过后登录可使用该头像。

系统管理员在“系统管理 → 用户管理”点击“待审核注册”，再通过行操作“审核注册”选择批准或拒绝，审核说明选填。批准后账号启用，按所申请角色登录；拒绝后保持禁止登录。普通修改、停用接口不能将待审核或已拒绝账号绕过审批启用。审批结果记录在系统审计日志中。

申请角色在审批前被停用时不能批准。管理员应拒绝该申请，再由申请人联系管理员安排重新申请。已使用的登录名和邮箱不能重复注册。管理员账号不能通过公开注册申请。

注册状态使用现有用户表的 `status` 字段：`PENDING` 为待审核，`REJECTED` 为已拒绝，批准后为 `ACTIVE`，不需要新增数据库列。

## 角色身份与供应商绑定

用户列表的“显示姓名”表示人员姓名，“角色身份”表示账号的有效角色；多角色以顿号分隔。无有效角色时显示“未分配角色”。

仅有效角色为单独 `SUPPLIER_PORTAL` 的启用账号可绑定供应商。管理员、采购、财务、质量等内部账号，以及混合了内部角色的账号，均不能绑定；前端隐藏相应操作，后端再次校验。每个门户账号只绑定一个启用供应商，同一供应商可以绑定多个门户账号。

供应商门户注册获批后，还需管理员在用户管理中绑定供应商才能访问门户业务。修改门户账号角色为内部身份时，原供应商绑定自动停用。历史上为内部账号设置的绑定通过开发环境身份更新脚本停用。

## 内置开发账号

内置账号使用互不重复的示例姓名，姓名不代表真实人员；角色名称仍由角色管理维护。演示供应商门户账号登录名为 `SupplierUser`；如存在历史账号，初始化前应核对身份和绑定，避免创建重复账号。

新环境的种子账号使用新登录名和示例姓名。已有开发库按以下顺序升级：

1. 先备份数据库，并确认备份可恢复。
2. 检查 `.env` 中的 `ADMIN_USERNAME`；若仍为 `system_admin`，先手动改为 `SystemAdmin`。迁移脚本不会修改 `.env`。
3. 在项目根目录运行 `uv run python scripts/update_demo_user_identities.py`。脚本仅允许 `development/dev` 环境，先检查全部账号，再在同一事务中改名并写审计日志。
4. 迁移成功后，再按需要运行 `uv run python scripts/seed_admin.py` 和 `uv run python scripts/seed_demo_accounts.py`。

脚本覆盖 12 个目标账号及其历史别名：`quality_inspector` 和 `quality` 对应 `QualityInspector`，`warehouse_receiver` 和 `warehouse` 对应 `WarehouseUser`，`supplier_portal` 和 `supplier_portal_demo` 对应 `SupplierUser`。如果同一目标存在多个历史账号，或目标已被其他账号占用，脚本会报告冲突并整体停止，需要人工核对，不会自动合并。只有名称大小写不同且实际为同一条用户记录时可以迁移。重复运行不会重复改名或重复写迁移审计日志。

迁移只更新登录名，保留用户 ID、密码、角色、部门、仓库范围和供应商绑定。`Antiboys`、`Zhangsan` 和 `Supplierportal` 不在演示迁移名单中。脚本不再更新显示名或停用供应商绑定。
