## 最终验收矩阵

| 范围 | 实際断言与结果 | 环境 / 替身 |
| --- | --- | --- |
| Broker 停机接收与恢复 | 停机时两个任务与 outbox 已提交；once 投递明确失败，持续投递器自动重连后两条变为 SENT；日志不含 RabbitMQ/MySQL 密码 | 独立 vhost `chemicalops-acceptance-20261008`，隔离 MySQL，真实 CLI / RabbitMQ |
| 两类队列隔离 | 仅运行 agent Worker 时 Agent 到达 WAITING_INPUT，资料任务仍为 QUEUED；documents Worker 执行前拒绝不存在用户，并在首次执行失败 | 两个独立 Python CLI；模型为本机 HTTP 替身，不代表真实模型回答 |
| 消费者强制退出 | 模型请求在途时强制退出真实 Worker，Job Object 结束任务子进程；过期租约回收后 token 增加并重投，旧代次不能 claim；恢复后 WAITING_INPUT 且执行次数为 2 | 真实 Windows CLI / 子进程 / MySQL / RabbitMQ |
| 失败隔离 | 永久权限错误生成 documents.failed outbox，持续投递器确认后可在失败队列读取同一 execution_id | 真实 Broker、失败发布及 ACK |
| 重复与丢 ACK | 并发重复消息执行一次，成功后重投不覆盖 checkpoint；发布确认后未标 SENT 的投递可重复发布；投递器租约互斥 | 真实 Broker / 隔离 MySQL；业务主体为明确测试替身 |
