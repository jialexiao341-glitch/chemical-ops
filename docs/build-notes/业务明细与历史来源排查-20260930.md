## 显示问题及修复

1. 对账服务原先将空快照的 `None` 来源摘要与当前来源摘要比较，版本 0 也被标记为 `source_changed=true`。现仅对已存在版本的记录比较摘要；版本 0 表示尚无历史快照，版本大于 0 缺少明细则明确提示版本记录异常。
2. 对账抽屉原先同时展示“来源已变化或尚未建立明细”和历史缺项提示。现分别展示来源变化、历史无快照、版本明细异常；其他全局/行级警告去重汇总，保留实际核查事项。
3. 历史对账不再展示不可用的金额精度控件和空的宽表格，改为说明卡片；有采购查看权限时提供关联订单入口。关联订单展示的是当前来源，不伪装成历史快照。
4. 对账列表新增“明细依据”，区分历史单据级记录与版本快照；历史记录的按钮命名为“对账依据”。
5. 历史发票不再提示用户手工填写不存在的行匹配，改为说明沿用单据级核验；其他实际警告继续保留，新版发票仍提供原匹配和版本功能。

以上改动不重算、回填或覆盖历史金额、审批和核验记录。可编辑对账单仍通过原生成接口建立新版本，保留权限、状态、来源与财务占用校验。

## 来源与验证边界

数量来自 `.cache/detail-data-audit-full.py` 的只读汇总，记录于 `.cache/detail-data-audit.log`；查询通过 `NOT EXISTS` 检查主单与明细，通过版本号检查对账当前行，通过 `IS NULL` 检查退货来源关联。临时文件不纳入生产数据或正式评估题集。

本轮未运行后端测试、前端类型检查或生产构建，先前文档中的通过记录属于之前的验证。没有历史数据库备份对比，因此不能证明从未发生数据删除；当前检查发现的是快照/来源缺项，未发现新版对账当前明细缺失。

本地浏览器只读查看 `REC-2026-0366`：历史说明卡片正常显示，原金额 493，未出现重复黄色提示、空明细表和不可用精度控件；“查看关联采购订单”正常进入 `/procurement/orders/1094`，未发现控制台错误。该结果仅验证一个历史对账示例，未验证全部发票状态或写操作。
