# ChemicalOps 分阶段开发任务计划

## 目标

本计划将后续工作拆分为四个相对独立的任务块。每个任务块都遵循以下流程：

```text
开发 → 针对性测试 → 手工验收 → 更新文档 → Git commit
```

一个任务块未完成并通过测试前，不把它和下一个任务块混在同一个提交中。

本计划不包含“先处理当前全量测试失败”这一项，按照当前确定的范围，直接推进以下四个任务块。

---

## 任务块一：完成前端核心业务链路

### 目标

将目前的通用 JSON 操作面板逐步替换为正式业务页面，打通采购到财务的主要演示链路：

```text
采购申请
 → 询价报价
 → 比价定标
 → 采购订单
 → 到货收货
 → 质量验收
 → 库存入库
 → 财务对账
```

### 开发范围

1. 采购申请页面
   - 申请单列表、详情、新建和编辑。
   - 明细行增加、删除和数量校验。
   - 提交、审批、驳回和取消。

2. 询价与供应商报价页面
   - 询价单列表、详情和状态展示。
   - 供应商选择、询价明细维护。
   - 供应商报价录入和报价明细展示。
   - 比价结果、报价快照和中选报价确认。

3. 采购订单页面
   - 订单列表、详情和状态时间线。
   - 提交、审批、下单、取消。
   - 展示关联采购申请、询价单、供应商和订单明细。

4. 到货、收货和质量验收页面
   - 到货计划登记。
   - 实际收货数量、物流信息和短交提示。
   - 质量验收结果、复检和异常提示。

5. 库存入库页面
   - 按已验收到货单创建入库。
   - 仓库、库位、批次和数量选择。
   - 库存余额和库存流水反馈。

6. 财务页面
   - 对账单创建和详情。
   - 发票录入、提交、核验和驳回。
   - 付款申请、审批和付款登记。
   - 结算确认及前置条件提示。

7. 横向页面补齐
   - 异常处理任务和评论。
   - 文件上传、附件列表、下载和关联。
   - 供应商门户订单确认和拒绝。

### 实施要求

- 优先复用现有 API、类型和样式，不重复创建业务规则。
- 所有写操作统一经过前端 API 封装。
- 表单错误优先展示后端返回的业务 `detail`。
- 状态按钮必须根据当前状态和用户权限动态显示。
- 业务页面要展示关联单据，避免用户在不同页面之间失去上下文。
- 对危险操作增加确认对话框。
- 不在前端复制库存、付款、验收等核心业务规则；前端只做体验层校验，后端仍是最终判断方。

### 测试与验收

- TypeScript 类型检查通过。
- 前端生产构建通过。
- 每个页面至少完成一次列表、详情、创建或状态操作的接口联调。
- 验证成功、后端业务错误、权限不足、资源不存在和重复提交场景。
- 手工走通一条完整链路：采购申请 → 询价报价 → 采购订单 → 收货 → 验收 → 入库。
- 手工验证财务对账的发票和付款前置条件提示。
- 手工验证附件上传、下载和业务资源权限控制。

### 完成标准

- 核心采购履约链路不再依赖通用 JSON 操作面板。
- 询价报价、财务、异常、文件和供应商门户至少具备可演示的正式页面。
- 页面操作结果、状态变化和错误提示与后端接口一致。

### 建议提交

```text
feat：完成前端核心业务链路页面
```

如果过程中出现独立缺陷修复，单独使用：

```text
fix：修复前端业务表单状态和错误提示
```

## 任务块二：加强数据安全和并发一致性

### 目标

让关键写接口在重复请求、并发请求和不同数据范围下保持可预测，支持多人同时使用。

### 开发范围

1. 统一写接口幂等
   - 梳理所有创建、提交、审批、执行类写接口。
   - 统一支持并校验 `Idempotency-Key`。
   - 相同用户、路径、方法、请求体和幂等键重复请求时回放原结果。
   - 相同幂等键但请求体不同，返回明确的冲突错误。
   - 前端 API 封装对需要幂等的写请求自动生成或接收业务幂等键。

2. 库存和履约并发控制
   - 为首次创建库存余额增加数据库唯一约束冲突后的重试策略。
   - 复核收货、入库、出库、调拨、退货和盘点的锁顺序。
   - 避免多个库存余额操作出现锁顺序不一致。
   - 复核审批、执行类接口的状态检查和行级锁。

3. 数据范围权限
   - 增加部门级数据范围控制。
   - 增加仓库级数据范围控制。
   - 增加供应商和业务单据归属校验。
   - 文件元数据、下载、附件列表和关联操作使用同一套资源权限判断。

4. 异常去重和任务一致性
   - 为同一来源单据、异常类型和未关闭状态增加稳定去重条件。
   - 复核异常任务的并发状态变更。
   - 防止重复扫描、重复通知和重复创建异常。

5. 数据库迁移验证
   - 梳理迁移执行顺序和依赖关系。
   - 验证新库初始化、旧库升级和重复执行保护。
   - 为关键迁移补充回滚或恢复演练记录。

### 测试与验收

- 重复提交同一个写请求不会重复创建业务数据。
- 不同请求复用同一个幂等键会返回冲突。
- 并发收货不会超收。
- 并发入库不会重复入账或丢失库存更新。
- 并发出库不会造成库存负数。
- 并发审批和执行不会绕过状态机。
- 部门、仓库、供应商无权限访问时返回明确的 403 或 404。
- 异常扫描重复执行不会生成重复未关闭异常。
- 数据库迁移可以在干净数据库和已有数据库上按顺序执行。

### 完成标准

- 关键写接口完成幂等清单并全部覆盖。
- 关键库存和履约接口完成并发测试。
- 数据范围权限至少覆盖部门、仓库、供应商和附件资源。
- 迁移执行顺序和恢复方案有可复现记录。

### 建议提交

```text
feat：完成关键写接口幂等与数据范围权限
```

独立缺陷修复使用：

```text
fix：修复库存余额首次创建的并发竞态
```

## 任务块三：完成生产化基础建设

### 目标

补齐从本地演示环境走向内部试用和生产候选环境所需的可观测性、安全性、可靠性和交付能力。

### 开发范围

1. 日志和请求追踪
   - 增加请求 ID。
   - 增加链路 ID 或可关联的 trace 标识。
   - 输出结构化 JSON 日志。
   - 记录关键业务操作、异常、慢请求和外部服务调用。
   - 前端错误与后端请求 ID可以关联。

2. 监控和告警
   - 统计 API 请求量、错误率、延迟和状态码。
   - 统计 AI 请求耗时、失败率和 token 或响应大小。
   - 统计文件解析、MinerU、ClamAV 和调度任务状态。
   - 为数据库连接、对象存储、AI 服务和后台任务增加健康检查。
   - 配置关键失败告警。

3. 数据库备份和恢复
   - 明确备份频率、保留周期和备份位置。
   - 编写数据库恢复步骤。
   - 定期执行恢复演练并记录结果。
   - 梳理迁移失败和回滚处理方式。

4. 对象存储和文件安全
   - MinIO 账号、密钥和桶策略不写入代码仓库。
   - 使用临时授权或服务端代理控制下载权限。
   - 生产环境启用 ClamAV 文件扫描。
   - 验证恶意文件、超大文件、伪造扩展名和解析失败场景。

5. 慢查询和性能
   - 开启数据库慢查询记录。
   - 检查 Dashboard、库存、通知、审计日志等高频查询。
   - 复核分页、索引和大数据量查询。
   - 对核心读接口和关键写接口分别进行压力测试。

6. CI 和安全交付
   - CI 执行后端检查、前端构建、迁移初始化和必要测试。
   - 增加依赖安全扫描和基础代码安全扫描。
   - 生成部署前检查清单。
   - 区分 development、staging 和 production 配置。

### 测试与验收

- 每个请求都能在日志中追踪到请求 ID。
- 500 错误不会把堆栈返回给前端，但日志中保留足够诊断信息。
- 数据库可以从备份恢复到可用状态。
- ClamAV 启用后，恶意样本会被拒绝，正常文件可以上传。
- MinIO 私有文件不能通过未授权 URL 直接访问。
- 慢查询可以被识别并定位到接口或 SQL。
- CI 能在干净环境完成构建和基础验证。
- 压力测试有明确的并发数、持续时间、成功率和延迟指标。

### 完成标准

- 具备可执行的日志、监控、告警、备份、恢复和部署文档。
- 文件安全和对象存储访问策略经过实际验证。
- CI 和安全扫描能够作为合并前门禁。
- 能够给出内部试用或生产候选环境的上线检查结果。

### 建议提交

```text
feat：完成生产化日志监控与安全基础设施
```

独立缺陷修复使用：

```text
fix：修复对象存储临时授权和文件下载权限
```

## 任务块四：增强 AI 只读助手稳定性

### 目标

在保持 AI 只读定位的前提下，提高查询可靠性、引用可解释性、权限安全性和远程服务稳定性。

### 开发范围

1. 引用和查询过程
   - 稳定展示附件、解析结果和业务数据来源。
   - 展示 AI 使用了哪些数据范围和查询类型。
   - 对无法访问的数据明确说明，而不是猜测。
   - 在前端 AI 工作台展示必要的查询 trace。

2. AI 请求日志和指标
   - 记录请求 ID、用户、会话、模型、耗时、结果状态和错误类型。
   - 记录流式请求的首 token 时间和完成时间。
   - 记录外部 DeepSeek、MinerU 请求失败和重试次数。
   - 敏感内容只记录摘要或哈希，不直接写入日志。

3. 查询边界和数据保护
   - 限制单次查询返回条数和上下文大小。
   - 对大范围查询增加分页、汇总或时间范围要求。
   - 对手机号、密钥、密码、财务敏感字段等进行脱敏。
   - 每次业务查询重新校验当前用户权限。
   - 严格保持只读，不开放直接 SQL 写入和高风险业务写操作。

4. 失败重试和降级
   - 对 DeepSeek 网络瞬时失败增加有限次数退避重试。
   - 对 MinerU 任务失败、超时和结果缺失给出明确状态。
   - 外部服务不可用时返回可理解的降级提示。
   - 避免流式响应中途失败后保存不完整的助手消息。

5. MinerU 和 ClamAV 生产验证
   - 验证 MinerU API key、配额、轮询间隔和结果存储。
   - 验证 PDF、Office、大文件和解析失败场景。
   - 验证 ClamAV 开启后 AI 附件不能绕过扫描。
   - 对解析状态增加超时回收和异常告警。

6. 后续写操作设计，只做方案不立即开放
   - AI 只生成采购申请、异常任务或付款申请草稿。
   - 用户必须在正式页面确认。
   - 最终写入必须调用现有业务 API。
   - 记录 AI 建议、用户确认、实际执行人和最终结果。
   - 本任务块暂不开放 AI 直接修改采购、库存或财务数据。

### 测试与验收

- 普通 AI 对话和 SSE 流式对话均能正确保存会话和消息。
- 引用来源顺序稳定，附件解析结果可以追溯。
- 没有权限的数据不会出现在 AI 上下文中。
- 超大查询会被限制或要求缩小范围。
- DeepSeek 瞬时失败会有限重试，持续失败会返回清晰错误。
- 流式响应中断不会写入伪造或不完整的最终答案。
- MinerU 成功、失败、超时和轮询回收均有测试。
- ClamAV 开关打开后，上传和 AI 使用之间不存在绕过路径。
- AI 不具备直接写入采购、库存、财务数据的接口权限。

### 完成标准

- AI 查询可解释、可追踪、可控范围地读取业务数据。
- 外部 AI 和文档解析失败时系统能够稳定降级。
- 敏感数据和附件权限经过验证。
- AI 仍保持“只读助手”定位，写操作只保留后续审批设计。

### 建议提交

```text
feat：增强 AI 只读助手的稳定性与可观测性
```

独立缺陷修复使用：

```text
fix：修复 AI 流式失败时的会话持久化问题
```

## 任务块执行顺序

```text
任务块一：前端核心业务链路
        ↓
任务块二：数据安全和并发一致性
        ↓
任务块三：生产化基础建设
        ↓
任务块四：AI 只读助手稳定性
```

任务块一和任务块二可以局部并行，但前端写接口最终应使用任务块二统一的幂等和权限约定。任务块三需要复用前两个任务块产生的日志、权限和接口约定。任务块四依赖文件安全、请求追踪和权限体系，因此放在生产化基础之后更容易一次完成。

## Git 提交规则

### 每个任务块的提交节奏

1. 开发期间可以有多个本地修改，但不要把未完成任务块提交成“完成”。
2. 完成任务块的开发后，先执行该任务块的针对性测试。
3. 测试失败时先修复，不提交“完成”提交。
4. 测试通过后更新本计划或对应进度文档。
5. 一个任务块使用一个主要完成提交。
6. 独立缺陷修复使用单独的 `fix：` 提交，不和下一个任务块混在一起。

### 提交格式

```text
feat：完成 <任务块或功能>
fix：修复 <具体问题>
test：补充 <测试范围>
docs：更新 <文档内容>
chore：调整 <构建或运维配置>
```

### 四个任务块的主要完成提交

```text
feat：完成前端核心业务链路页面
feat：完成关键写接口幂等与数据范围权限
feat：完成生产化日志监控与安全基础设施
feat：增强 AI 只读助手的稳定性与可观测性
```
