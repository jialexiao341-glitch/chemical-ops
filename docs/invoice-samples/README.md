# 发票行匹配开发样本

这是一组结构化模拟发票，不是真实税务发票，也没有票面图片或 PDF。票面字段足以验证本阶段的人工匹配流程，不能证明真实发票识别和财务规则的准确性。

脚本新增六套独立的模拟采购订单、到货和对账记录，复用现有供应商、产品及财务账号；所有模拟单据明确标注开发用途。不修改原有业务记录，不执行入库、出库或付款。模拟到货的已验收状态只是场景设定，不代表完成实验室检验。

## 页面使用

财务专员登录 → 财务管理 → 供应商发票 → 查找 `DEV-SIM-` 开头的号码 → 点击“行匹配”。财务负责人可查看匹配和差异说明，再在列表执行人工核验；须与提交人及匹配人不同。

| 号码 | 场景 | 预期行为 |
| --- | --- | --- |
| DEV-SIM-FULL-01 | 全额、两产品行 | 已提交，等待另一人核验 |
| DEV-SIM-SPLIT-01 / 02 | 分两张票 | 可分别匹配，同一产品行累计不超应付 |
| DEV-SIM-MULTI-01 | 一票多产品行 | 分别保存各行不含税及税额 |
| DEV-SIM-AMOUNT-01 | 匹配合计不符 | 可保存草稿，补齐金额前不能提交 |
| DEV-SIM-TAX-01 | 票面税额比例不同 | 必须填写差异处理说明，再交由另一人复核 |
| DEV-SIM-REJECT-01 / 02 | 驳回与重新录入 | 旧票释放额度，新票占用；旧票直接重提会被重新校验 |

两产品行的对账金额分别为 1,130（不含税 1,000、模拟税额 130）和 1,000（税额 0），合计 2,130 CNY。这里的税率仅用于测试，不作为实际产品税务口径。

匹配不自动调整票面金额，也不自动吸收尾差。行价税合计及整单累计不得超过应付；票面总额低于对账金额可作为部分开票。票面总额超出应付的样本由隔离测试验证接口拒绝，不保留为有效发票。

差异核查入口：采购订单 → “核对财务差异” → 保存当前快照 → 建立或补充核查清单。清单包括订单行、财务主单和各发票；记录处理办法、关联单据编号及结论，另一人复核。已复核后须先重开，才能修改处理说明或负责人。发票重新匹配、提交、核验、驳回或作废后，关联订单的旧核查结果自动重开并记录原因，防止依据变化后仍显示已复核。

## 重跑与材料

从项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/seed_invoice_matching_samples.py --dry-run
.\.venv\Scripts\python.exe scripts/seed_invoice_matching_samples.py
```

脚本仅允许开发/测试环境，固定编号确保重复运行不重复新增、不覆盖用户已处理的样本。`manifest.json` 保存业务入口编号；`模拟发票清单.csv` 可用 Excel 查看票面字段。

历史版本 0 对账单继续采用单据级核验，未匹配的旧发票不猜测产品行归属。当前不支持已核验发票冲销、红字发票、付款行分配或税务平台验真。
